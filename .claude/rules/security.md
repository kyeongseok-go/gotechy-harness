# 보안 규칙 (API·인증·DB 영역)

이 파일을 건드리는 중이라면 docs/SECURITY.md의 해당 체크리스트를 먼저 확인한다.

- 모든 핸들러는 ①인증 확인 ②인가(소유권) 확인 ③입력 스키마 검증 순서를 지킨다.
- SQL은 파라미터 바인딩만. 문자열로 쿼리를 조립하는 코드를 발견하면 그 자리에서 수정한다.
- 시크릿·토큰을 로그에 남기지 않는다. 에러 응답에 내부 구조(스택·쿼리)를 노출하지 않는다.
- 사용자 제공 URL을 서버에서 fetch할 때는 허용 목록 검증 (SSRF 방어).
- 레이트 리밋 없는 공개 엔드포인트를 추가하면 tech-debt이 아니라 즉시 수정 대상이다.

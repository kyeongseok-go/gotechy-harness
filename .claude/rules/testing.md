# 테스트 규칙

- 새 테스트는 먼저 실패하는 것을 확인한다 (RED → GREEN). 통과하는 테스트를 나중에 끼워 넣지 않는다.
- 테스트 이름은 동작을 서술: `"만료된 토큰이면 401을 반환한다"` (구현 세부가 아니라 계약을 검증).
- Service 레이어 테스트가 최우선 — UI 스냅샷 테스트로 커버리지를 부풀리지 않는다.
- 모킹은 경계(Repo·외부 API)에서만. Service 내부를 모킹하기 시작하면 설계를 의심한다.
- flaky 테스트는 skip하고 tech-debt-tracker에 기록 — 주석 처리로 숨기지 않는다.
- E2E는 핵심 사용자 여정 단위 (페이지 단위 아님). 셀렉터는 role·label 우선.

# 테스트 규칙 — SDD + 수용 테스트 먼저 (2026-10-14 개정)

- **순서: 스펙 → 수용 테스트(실패 확인) → 구현.** 스펙·계약·ExecPlan Validation의 수용 기준을 먼저 테스트로 옮기고, 실패하는 것을 본 뒤 구현한다. 대상: 계약·lint·결정·서명·상태 전이 같은 핵심 로직. (`src/**`를 고치기 전에 이 규칙이 로드되도록 paths에 넣었다.)
  - 이유: 에이전트가 코드를 먼저 쓰고 테스트를 나중에 쓰면, 테스트가 구현을 베껴 버그까지 정답으로 고정한다. 먼저 쓴 테스트는 "끝났다"의 객관적 판정 기준이 된다.
- **예외 — 동작을 모르는 외부 경계**(에이전트 CLI·외부 API·OS 기능): 먼저 작은 실험으로 실제 동작을 확인하고(ExecPlan M0 방식, 결과를 Surprises에 기록), 확인한 동작을 테스트로 고정한다.
- 테스트 이름은 동작을 서술한다: `"결정 파일을 건드리면 되돌리고 failed"` (구현 세부가 아니라 계약을 검증).
- 핵심 로직 테스트가 최우선 — UI 스냅샷 테스트로 커버리지를 부풀리지 않는다.
- 모킹은 경계(외부 CLI·네트워크·Repo)에서만. 재현이 필요하면 녹화 재생(fake 어댑터)을 쓴다. 내부 로직을 모킹하기 시작하면 설계를 의심한다.
- flaky 테스트는 skip하고 tech-debt-tracker에 기록 — 주석 처리로 숨기지 않는다.
- E2E는 핵심 사용자 여정 단위. LLM을 실제로 부르는 검증은 증거 1회만 남기고, 반복 검증은 녹화 재생으로 한다.

# 코드 리뷰 체크리스트

구현을 넘기기 전 자기 리뷰(절차 8단계)와, 다른 사람이나 다른 에이전트의 변경을 리뷰할 때 연다.

## 승인 기준

- 변경이 코드 전체의 건강을 확실히 개선하면, 완벽하지 않아도 승인한다. 완벽한 코드는 없다. 근거: https://google.github.io/eng-practices/review/reviewer/standard.html
- 지적마다 `[막는]`(고치기 전 병합 불가), `[권장]`(이번에 고치면 좋음), `Nit:`(선택, 사소함) 중 하나를 붙인다.
- 리뷰 요청에는 1영업일 안에 응답한다. 근거: https://google.github.io/eng-practices/review/reviewer/speed.html
- 모든 지적은 "반영" 또는 "기각(사유)"으로 끝난다. 열린 채로 병합하지 않는다.

## 읽는 순서

1. 변경 설명을 읽고 무엇을, 왜 바꾸는지 한 문장으로 말해 본다. 못 하면 설명 보강부터 요청한다.
2. 핵심 로직 파일을 먼저, 그다음 테스트, 그다음 나머지를 읽는다.
3. 사람이 쓴 줄은 모두 읽는다. 생성 코드와 lockfile은 생성 명령과 바뀐 패키지 버전만 확인한다.
4. 400줄(생성 코드, lockfile 제외)을 넘으면 리뷰하지 않고 쪼개 달라고 한다.

## 체크리스트

앞의 9개는 Google의 "리뷰에서 볼 것"(https://google.github.io/eng-practices/review/reviewer/looking-for.html)을 따르고, 뒤의 항목은 이 스킬이 더했다.

| # | 항목 | 통과 조건 |
|---|---|---|
| 1 | 설계 | 이 코드가 이 자리에 맞고, 지금 필요한 일만 한다. 미래를 위한 추상화 없음 |
| 2 | 기능 | 수용 기준대로 동작한다. 경계값, 빈 입력, 동시 요청, 실패 응답을 생각했다 |
| 3 | 복잡도 | 읽는 사람이 한 번에 이해한다. 함수 하나가 한 가지 일을 한다 |
| 4 | 테스트 | 동작마다 테스트가 있고, 코드가 깨지면 실제로 실패한다. 이름이 동작을 서술한다 |
| 5 | 이름 | 이름만 읽고 무엇을 하는지 예측된다. 함수는 동사, 타입은 명사 |
| 6 | 주석 | "무엇"이 아니라 "왜"(코드로 말할 수 없는 제약)를 적었다 |
| 7 | 스타일 | 포매터와 린터 결과 그대로다. 스타일 취향은 `Nit:` |
| 8 | 일관성 | 같은 문제를 저장소의 기존 방식으로 풀었다. 새 방식이면 이유가 있다 |
| 9 | 문서 | 동작, 명령, 설정이 바뀌었으면 README, 스펙, ADR이 같은 변경에 있다 |
| 10 | 경계 | 외부 입력은 진입점 한 곳에서 파싱된다. 안쪽에 `any`, 캐스팅, 반복 검증 없음 |
| 11 | 에러 | 삼킨 에러 없음. 올리는 에러에 맥락이 있다. 사용자에게 내부 구조가 보이지 않는다 |
| 12 | 의존성 | 새 의존성은 정확한 버전, lockfile 포함, ADR 있음, 라이선스와 취약점 확인 |
| 13 | 보안 | 핸들러가 인증, 인가(소유권), 입력 검증 순서를 지킨다. SQL은 바인딩만. 비밀이 코드와 로그에 없다. 사용자 URL을 서버에서 부르면 허용 목록. 공개 엔드포인트에 레이트 리밋 |
| 14 | 데이터 | 마이그레이션이 옛 코드와 함께 돌아도 깨지지 않는다. 잠금 시간 상한, 되돌리는 절차가 있다 |
| 15 | 성능 | 반복문 안의 쿼리(N+1) 없음. 목록에 상한이 있다. 큰 테이블 쿼리에 인덱스 근거가 있다 |
| 16 | 동시성 | 공유 상태에 경쟁이 없다. 취소와 타임아웃이 있다. 재시도는 멱등한 작업에만 |
| 17 | 잘한 점 | 잘한 것을 하나 이상 구체적으로 적는다 |

13번에서 하나라도 걸리면 `gotechy-security` 스킬로 넘긴다.

## 결과 형식

```
판정: 승인 | 고친 뒤 승인 | 변경 요청
요약: 한 문장
[막는] path/file.ts:42 무엇이 문제인지, 왜, 제안
[권장] ...
Nit: ...
잘한 점: ...
체크리스트: 17개 중 N개 통과
```

## 자기 리뷰에서 특히 볼 것 (AI가 남기기 쉬운 흔적)

- 디버그 출력(`console.log`, `print`, `fmt.Println`)과 주석 처리한 코드.
- 추적 번호 없는 TODO.
- 사유 없는 검사 끄기 주석.
- 테스트가 구현을 그대로 베낀 경우(기대값을 구현 함수로 계산).
- 실제로 실행하지 않은 명령을 실행한 것처럼 적은 보고.

# gotechy-comply-kr bar: 한국 법 요구사항 추출의 최고 수준 기준

법 요구사항 표(`docs/compliance/<슬러그>.md`)를 판정하거나 등급을 매길 때 연다. 체크리스트와 등급표의 원본이다.

> 법률 자문이 아니다. 이 bar는 "법이 요구하는 것을 빠짐없이 찾아 제품 요구사항으로 바꿨는가"를 판정한다. 조문 해석이 사실관계에 따라 갈리는 부분은 전문가에게 넘긴다. 시행일은 원문에서 다시 확인한다.

## 이 bar가 지키는 것

작은 제품 팀이 모르는 사이에 법을 어기는 일을 막는다. 구체적으로는 세 가지다. 기능마다 걸리는 법과 조문을 빠짐없이 찾는다. 각 의무를 담당과 검증 방법이 있는 제품 요구사항(화면, 데이터, 로그, 문서)으로 바꾼다. 그리고 근거 없는 주장을 하지 않는다. 조문 번호와 원문 링크와 확인일이 없는 요구사항은 요구사항이 아니다. 법이 요구하는 것, 정부 지침이 권장하는 것, 팀이 고른 것을 섞지 않는다.

## 측정형 체크리스트

`[기계]`는 도구나 명령으로 판정하고 줄 끝에 `도구: <이름이나 명령>`을 적는다. `[사람]`은 리뷰로 판정한다. "(하네스 기본값)"이라고 쓴 수치는 법이 정하지 않아 하네스가 정한 값이다.

### R. 요구사항 표의 품질

- R1 [기계] 요구사항 행마다 법 이름과 조문이 항이나 호까지 있다. 조문 없는 행 0개. 도구: "법과 조문" 열을 정규식 `제[0-9]+조(의[0-9]+)?(제[0-9]+항)?`로 검사(awk와 grep)
- R2 [기계] 행마다 원문 URL(law.go.kr 또는 규제 기관 누리집)과 확인일이 있고, 확인일은 90일 이내다(하네스 기본값). 도구: `grep -E '^\| R[0-9]+ ' docs/compliance/<슬러그>.md | grep -vcE 'https://.*[0-9]{4}-[0-9]{2}-[0-9]{2}'` 0, 날짜는 `date`와 비교
- R3 [기계] 행마다 담당과 검증 방법(`[기계]` 또는 `[사람]`)이 있다. 빈 칸 0개. 도구: `grep -E '^\| R[0-9]+ ' docs/compliance/<슬러그>.md | awk -F'|' '$8 ~ /^ *$/ || $9 !~ /\[(기계|사람)\]/' | wc -l` 0
- R4 [기계] 제품 요구사항 열에 "준수한다", "적절히", "충분히", "필요 시" 같은 판정 불가 표현 0건. 도구: grep
- R5 [사람] `triggers.md`의 질문 26개에 모두 답이 있고, "아니오"에도 이유가 있다.
- R6 [기계] 문서 맨 위에 법률 자문이 아니라는 문장과 "전문가 확인 필요" 절이 있다. 도구: `grep -c '법률 자문이 아니다\|## 5. 전문가 확인 필요' docs/compliance/<슬러그>.md` 2
- R7 [사람] 구분 열(법정 의무, 지침 권장, 팀 선택)이 맞다. 지침 권장을 법정 의무로, 팀 선택을 법 요구로 쓴 행 0개.
- R8 [사람] 시행 전 조문은 "시행 예정"과 날짜로 표시되고 "다시 볼 날"에 들어 있다.
- R9 [기계] 출시 전에 끝내야 하는 법정 의무 행은 상태 칸에 "출시 차단"이 붙어 있고, `gotechy-ship`은 상태가 완료가 아닌 출시 차단 행이 0개여야 통과시킨다. 도구: `grep -E '^\| R[0-9]+ ' docs/compliance/<슬러그>.md | grep '출시 차단' | grep -vc '| 완료'`

### P. 개인정보

- P1 [사람] 처리방침이 개인정보 보호법 제30조제1항과 시행령 제31조제1항의 항목 중 해당하는 것을 하나도 빠뜨리지 않는다. 판정표는 `requirements-template.md` 4절.
- P2 [기계] 모든 화면에서 "개인정보 처리방침" 링크에 닿고, 다른 고지와 글자 크기나 색으로 구분된다(시행령 제31조제2항, 작성지침이 인용한 표준지침 제20조). 도구: e2e 테스트.
- P3 [기계] 필수, 선택, 마케팅 동의가 따로 있고, 선택과 마케팅을 거부해도 가입이 끝난다(제16조제3항, 제22조제1항, 제5항). 도구: e2e 테스트.
- P4 [사람] 처리방침의 수탁자 표와 국외 이전 절이 실제로 개인정보를 보내는 외부 서비스 목록(클라우드, 메일, 분석, LLM API)과 같다(제26조제2항, 제28조의8). 외부 서비스를 더하는 변경마다 확인한다.
- P5 [기계] 보유 기간이 지난 개인정보를 파기하는 작업과 실행 기록이 있다(제21조). 도구: 파기 작업 테스트와 실행 로그 조회
- P6 [사람] 만 14세 미만이 쓸 수 있으면 시행령 제17조의2의 법정대리인 확인 방법 하나가 구현돼 있다(제22조의2).
- P7 [기계] 비밀번호 일방향 암호화, 고시가 정한 7종(주민등록번호, 여권번호, 운전면허번호, 외국인등록번호, 신용카드번호, 계좌번호, 생체인식정보) 저장 암호화, 인터넷 구간 전송 암호화(안전성 확보조치 기준 제7조). 접속기록 1년 이상, 해당 시 2년 이상 보관(제8조). 기술 검증은 `gotechy-security` 스킬과 같이 한다. 도구: 저장 컬럼 암호화 테스트, TLS 검사(예: `curl -v`로 인증서 확인), 로그 보관 설정 grep
- P8 [사람] 유출 대응 runbook에 72시간 통지 문안(제34조제1항의 항목), 신고 기준(1천명 이상, 민감정보나 고유식별정보, 외부 불법 접근), 신고처(개인정보보호위원회나 한국인터넷진흥원)가 있다(시행령 제39조, 제40조). 모의 훈련 연 1회(하네스 기본값).
- P9 [사람] 자동화된 결정이 있으면 거부와 설명 요청 경로가 있고 기준과 절차가 공개돼 있다(제37조의2).

### M. 마케팅과 광고

- M1 [기계] 광고 이메일 제목이 "(광고)"로 시작하고, 본문에 전송자 명칭, 이메일, 전화, 주소, 수신 거부 안내가 있다(정보통신망법 제50조제4항, 시행령 별표 6). 도구: 메시지 템플릿 테스트.
- M2 [기계] 오후 9시부터 오전 8시까지의 광고 발송은 별도 동의가 있는 수신자에게만 간다(전자우편 제외, 제50조제3항, 시행령 제61조제2항). 도구: 발송 스케줄러 테스트.
- M3 [기계] 수신 동의일부터 2년마다 동의 확인 메시지를 보내는 작업이 있다(시행령 제62조의3). 도구: 스케줄러 작업 테스트
- M4 [기계] 수신 거부나 철회는 즉시 발송 대상에서 빠지고 처리 결과가 통지된다(제50조제2항, 제7항). 도구: 수신 거부 뒤 발송 대상 조회 테스트
- M5 [사람] 후기와 추천 광고에 경제적 이해관계를 공개하고, AI 가상인물은 가상인물임을 공개한다(추천보증 심사지침 Ⅴ.5, Ⅴ.6).

### A. AI 기능

- A1 [사람] 생성형이나 고영향 AI 기반 서비스임을 화면이나 약관으로 미리 알린다(AI 기본법 제31조제1항, 시행령 제23조제1항). 과태료 대상이다(제43조제1항제1호).
- A2 [기계] 생성 결과물에 사람이 인식하는 표시가 있거나, 기계 판독 표시와 1회 이상 안내 문구가 있다(제31조제2항, 시행령 제23조제2항). 도구: 결과물 화면 e2e 테스트.
- A3 [사람] 실제와 구분하기 어려운 합성 음성, 이미지, 영상에는 이용자가 명확히 인식하는 표시가 있다(제31조제3항).
- A4 [사람] 고영향 AI 해당 여부를 검토한 기록이 있다. 해당 없음이어도 이유를 쓴다(제33조제1항).
- A5 [사람] 프롬프트와 결과물의 저장, 학습 활용 여부, 학습 거부 방법이 처리방침에 있다(작성지침 2026.4 부록, 지침 권장).

### W. 접근성

- W1 [기계] 핵심 화면에서 자동 접근성 검사 위반 0건. 기준은 한국형 웹 콘텐츠 접근성 지침 2.2. 도구: axe-core(@axe-core/playwright 등)
- W2 [사람] 자동 검사가 못 보는 항목(키보드만으로 전체 흐름, 화면낭독기로 핵심 흐름, 대체 텍스트의 뜻)을 수동 점검한 기록이 있다.
- W3 [사람] 장애인이 대체 수단을 요청할 경로가 있고 7일 안에 제공하는 절차가 있다(장애인차별금지법 시행령 제14조제3항).

### C. 거래

- C1 [기계] 판매 화면 하단에 상호, 대표자, 주소, 전화, 이메일, 통신판매업 신고번호가 있다(전자상거래법 제10조, 제13조제1항). 도구: e2e 테스트
- C2 [기계] 가격을 처음 보여 주는 화면에 필수 비용을 포함한 총금액이 있다(제21조의2제1항제1호). 도구: e2e 테스트
- C3 [기계] 해지와 탈퇴는 가입과 같은 수단(온라인 가입이면 온라인)으로 할 수 있고, 단계 수가 가입 단계 수보다 많지 않다(제21조의2제1항제4호, 단계 수 비교는 하네스 기본값). 도구: 가입과 해지 흐름 e2e 테스트의 단계 수 비교
- C4 [기계] 정기결제 증액이나 무료에서 유료 전환 30일 전까지 동의를 받는 작업이 있다(제13조제6항, 시행령 제20조의2). 도구: 스케줄러 작업 테스트
- C5 [기계] 다른 상품이나 부가 서비스 선택항목이 미리 선택돼 있지 않다(제21조의2제1항제2호). 도구: e2e 테스트
- C6 [사람] 청약철회 기한과 방법이 결제 전에 고지된다(제13조제2항제5호, 제17조).

| A (최고 전문가) | 체크리스트 전부 통과. R1, R2, R3, P3, M1, A2, W1이 CI에서 기계로 검사된다. 최근 4주 회귀 0건(동의와 표시 테스트 실패 0, 확인일 초과 행 0). |
| B (출시 가능) | 전부 통과했지만 일부를 수동으로 확인한다. |
| C (부채 있음) | 법정 의무는 모두 충족. 지침 권장이나 팀 선택 항목의 미달이 담당과 기한과 함께 부채 목록에 있다. |
| D (위험) | 법정 의무 미달이 하나라도 있거나, 조문 없이 법 요구를 주장한 행이 있거나, 미달이 기록조차 없거나, 시행일을 원문에서 확인하지 않았다. |

## 최고 전문가가 더 하는 것

1. **조문 단위로 추적한다.** 요구사항마다 조, 항, 호와 원문 링크와 확인일을 단다. 감사나 분쟁 때 "어느 조문 때문에 이 화면이 이렇다"를 바로 보여 줄 수 있다.
2. **시행일 달력을 둔다.** 2026년에만 개인정보 보호법(3월 개정, 9월 시행), 안전성 확보조치 기준(7월), 처리방침 작성지침(4월), AI 기본법(1월 개정, 7월 일부 시행), 전자상거래법(7월 시행)이 바뀌었다. 시행 예정 조문(개인정보 보호법 제32조의2제1항 단서 2027-07-01, 전자상거래법 제20조의5 2027-01-21)을 미리 표에 넣는다.
3. **법정 의무, 지침 권장, 팀 선택을 나눈다.** 처리방침 작성지침도 생성형 AI 항목을 "기재하는 것이 바람직함"으로 쓴다. 섞으면 과잉 준수로 일정이 밀리거나 의무를 권장으로 착각한다.
4. **데이터 목록 하나에서 모든 고지를 만든다.** 수집 항목, 근거, 보유 기간, 수탁자, 국외 이전을 한 표로 관리하고 처리방침, 동의 화면, 수탁자 표를 거기서 만든다. 외부 서비스를 하나 더할 때 세 곳이 어긋나는 일이 없다.
5. **동의를 증거로 남긴다.** 누가 언제 어떤 문구 판에 동의했는지 저장한다. 최소 수집과 동의 없는 처리의 입증책임은 처리자에게 있다(개인정보 보호법 제16조제1항, 제22조제3항).
6. **72시간을 미리 연습한다.** 유출을 알게 된 때부터 통지와 신고까지 72시간이다(시행령 제39조, 제40조). 문안과 연락처와 판단 기준을 미리 써 두고 1년에 한 번 모의로 돌린다.
7. **모르는 것은 모른다고 쓴다.** 조문을 추정해 채우지 않고 "전문가 확인 필요"로 올린다. 신용정보법처럼 범위 밖이면 트리거만 남긴다.

## 흔한 실패와 고치는 법

| 실패 | 고치는 법 |
|---|---|
| "법적으로 필요합니다"라고만 쓰고 조문이 없다 | 조문과 원문 링크가 없으면 요구사항으로 쓰지 않는다. 확인 못 하면 "전문가 확인 필요"(R1, R2) |
| 학습 지식의 옛 조문이나 시행일을 그대로 쓴다 | 원문을 다시 열어 현행 판과 시행일을 쓰고 확인일을 단다 |
| 지침 권장을 법정 의무로 쓰거나 반대로 쓴다 | 구분 열로 나눈다(R7) |
| LLM API나 분석 도구를 붙였는데 처리방침의 수탁자와 국외 이전 절은 그대로다 | 외부 서비스를 더하는 변경에 처리방침 확인을 묶는다(P4) |
| 모든 동의를 체크박스 하나로 묶는다 | 필수, 선택, 마케팅을 나누고 선택 거부로도 가입되게 한다(P3) |
| 마케팅 동의 없이 이벤트 문자나 푸시를 보낸다 | 수신 동의와 마케팅 목적 처리 동의를 따로 받고 발송 전에 확인한다(M1~M4) |
| AI 기능을 출시하면서 AI 기반이라는 사전 고지를 빠뜨린다 | 첫 사용 화면이나 약관에 고지하고 결과물 표시를 테스트한다(A1, A2) |
| 가입은 앱에서 한 번에 되는데 해지는 전화로만 된다 | 같은 수단, 같은 단계 수로 해지 경로를 만든다(C3) |
| 유출이 나면 그때 법을 찾는다 | runbook과 문안을 미리 두고 연습한다(P8) |
| 조문 해석을 단정해 법률 자문처럼 쓴다 | 문서 맨 위 면책, 해석이 갈리는 행은 전문가에게(R6) |

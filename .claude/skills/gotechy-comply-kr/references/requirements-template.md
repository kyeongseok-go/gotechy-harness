# 법 요구사항 표 템플릿

사용자 프로젝트에 `docs/compliance/<슬러그>.md`를 만들거나 고칠 때 연다. `docs/compliance/` 폴더가 없으면 만든다.

## 행을 쓰는 규칙

- 한 행은 조문 하나와 제품 요구사항 하나다. 한 조문이 여러 화면에 걸리면 행을 나눈다.
- 조문은 조, 항, 호까지 쓴다(예: 개인정보 보호법 제22조제1항제7호). 조만 쓰면 검증할 수 없다.
- 제품 요구사항은 화면, 데이터, 로그, 문서 중 무엇이 어떻게 되어야 하는지 검증 가능한 문장으로 쓴다. "법을 준수한다", "적절히 고지한다"는 요구사항이 아니다.
- 검증 방법은 [기계](테스트 이름, 검사 명령) 또는 [사람](누가 무엇을 보고 판정) 중 하나로 쓴다.
- 구분 열: 법정 의무(조문이 직접 요구), 지침 권장(정부 지침이 권장), 팀 선택(법이 요구하지 않지만 팀이 정함). 셋을 섞지 않는다.
- 해석이 갈리거나 사실관계에 따라 달라지는 행은 상태를 "전문가 확인 필요"로 둔다.
- 원문 URL과 확인일을 행마다 쓴다. 확인일이 90일을 넘으면 다시 확인한다(하네스 기본값).
- 상태 칸 값은 미착수, 진행 중, 완료, 전문가 확인 필요, 원문 확인 필요 중 하나다. 출시 전에 끝내야 하는 행(법정 의무이고 미달이면 출시하면 안 되는 것)은 상태 뒤에 ", 출시 차단"을 붙인다(예: `진행 중, 출시 차단`). `gotechy-ship`은 상태가 완료가 아닌 출시 차단 행이 남아 있으면 출시 게이트를 통과시키지 않는다.

## 처리방침과 동의 문구 초안을 쓸 때

- 개인정보보호위원회의 처리방침 작성지침(2026.4.)과 처리방침 표준(안)(2026.2.)의 순서와 용어를 따른다.
- 생성형 AI 기능이 있으면 작성지침 부록의 다섯 항목(의도된 용례, 프롬프트와 결과물 수집 여부, 학습 활용 여부, 보유 기간, 학습 거부 방법)을 넣는다. 지침 권장 사항이므로 구분 열에 "지침 권장"으로 쓴다.
- 문구 초안은 "초안"이라고 표시하고, 출시 전에 대표가 승인한다.

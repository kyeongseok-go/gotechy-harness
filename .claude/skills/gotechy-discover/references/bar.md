# gotechy-discover 기준점 (bar)

이 bar는 "만들 가치가 있다"는 판단이 우리 머릿속 추측이 아니라 대상 고객의 과거 행동에서 나왔는지를 지킨다. 최고 수준의 discovery 팀은 매주 고객을 만나고, 인터뷰에서 자기 아이디어를 꺼내지 않으며, 해결책을 여러 개 비교하고, 가장 위험한 가정을 가장 싼 실험으로 먼저 깨 본다. 이 기준을 통과하지 못한 아이디어는 스펙으로 넘어가지 않는다.

원천에서 가져온 핵심 사실:

- Torres는 continuous discovery를 "만드는 팀이 매주 고객과 만나 원하는 결과를 위해 작은 조사를 하는 것"으로 정의한다. 만드는 사람이 직접 고객과 이야기해야 한다.
- OST를 시작하기 전에 이야기 중심 인터뷰 3~4건이 필요하고, 기회 공간은 인터뷰 3~4건마다 다시 본다. 대상 기회 하나에 해결책을 최소 3개 놓고 비교한다.
- 인터뷰는 해결책을 시험하는 자리가 아니다. 미래 질문과 닫힌 질문을 피하고 "지난번에 ~했을 때"로 특정한 과거 한 번을 파낸다. 스냅숏은 인터뷰 직후에 만든다(인터뷰 20~30분, 스냅숏 15~25분).
- Mom Test 세 규칙: 아이디어 말고 고객의 삶을 이야기한다, 과거의 구체적 사실을 묻는다, 덜 말하고 더 듣는다. 진지함의 증거는 약속이다(시간, 평판 위험, 돈).
- Christensen Institute는 job을 "특정 상황에서 목표를 향해 이루려는 진전"으로 보고 기능, 사회, 감정 차원을 함께 본다.
- Strategyn 기회 공식: `importance + max(0, importance - satisfaction)`.
- Bland의 가정 지도는 중요도와 증거 두 축으로 배치하고, 중요한데 증거가 없는 오른쪽 위를 먼저 실험한다. 가설은 "우리는 ~라고 믿는다"로 쓴다.
- Test Card는 가설, 시험 방법, 측정 지표, 합격 기준(문턱값) 네 칸이다.
- Cagan의 네 위험: 가치(사려 하거나 쓰려 하는가), 사용성(쓰는 법을 알아내는가), 실현 가능성(가진 시간, 기술, 사람으로 만들 수 있는가), 사업 타당성(사업의 여러 면에서 성립하는가).
- Shape Up: appetite는 추정이 아니라 쓸 시간의 예산이고 설계를 깎는 기준이다. 피치는 문제, appetite, 해결, rabbit hole, no-gos 다섯 재료이고 좋은 문제 정의는 현재 방식이 왜 안 되는지 보여 주는 구체적 이야기 하나다. 기술 전문가에게는 "가능한가"가 아니라 "이 기간 안에 가능한가"를 묻는다.

## 측정형 체크리스트

`<문서>`는 `docs/discovery/<슬러그>.md`다.

1. **인터뷰 수** [기계] `grep -cE '^### I-[0-9]+' <문서>`. 합격선: 3 이상(Torres의 3~4건). 지인, 가족 인터뷰는 따로 표시하고 이 수에 넣지 않는다. 도구: grep
2. **인터뷰마다 원문 인용** [기계] `grep -cE '^> "' <문서>`. 합격선: 인터뷰 수 이상. 도구: grep
3. **질문지의 미래 의향, 의견 질문** [기계] `grep -nE '(하시겠|쓰시겠|사시겠|쓸 건가요|살 건가요|있으면 좋|좋을 것 같|원하시나요|어떠세요)' <문서>`. 합격선: 3절에서 0줄. 도구: grep
4. **기회의 근거 연결** [기계] `grep -E '^- O[0-9]+' <문서> | grep -vc '근거: I-'`. 합격선: 0(근거 없는 기회 0개). 도구: grep
5. **해결책 후보 수** [기계] `grep -cE '^- S[0-9]+' <문서>`. 합격선: 3 이상. 도구: grep
6. **실험 카드 합격선** [기계] `grep -E '^- 합격선:' <문서> | grep -vcE '[0-9]'`. 합격선: 0, 그리고 합격선 줄이 1개 이상. 도구: grep
7. **개인정보** [기계] `grep -nE '01[016789]-?[0-9]{3,4}-?[0-9]{4}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+[.][A-Za-z]{2,}' <문서>`, 저장소에 gitleaks가 있으면 함께 돌린다. 합격선: 0줄. 도구: grep, gitleaks
8. **증거 등급 표지** [기계] `grep -oE '\[(행동|이야기|의견|가정)\]' <문서> | wc -l`. 합격선: 4절 인용 수와 5절 기회 수의 합 이상. 도구: grep, wc
9. **기회가 해결책이 아님** [사람] 기회 문장마다 그것을 푸는 서로 다른 해결책 2개를 떠올릴 수 있는가. 합격선: 모든 기회 통과.
10. **인용이 원문 그대로** [사람] 노트 원본과 대조한다. 합격선: 다듬거나 합친 인용 0개.
11. **대상 고객 일치** [사람] 인터뷰 대상이 2절 고객 정의(상황, 최근 행동)에 맞는가. 합격선: 맞지 않는 사람은 1번 수에서 뺐다.
12. **네 위험 검토** [사람] 6절에 가치, 사용성, 실현 가능성, 사업 타당성 가정이 각 1개 이상. 합격선: 4종 모두.
13. **실험 우선순위** [사람] 7절 첫 실험이 6절의 "중요, 증거 없음" 칸 가정을 겨누는가. 합격선: 겨눈다.
14. **사전 등록** [사람] 합격선을 적은 날짜가 결과 날짜보다 앞서는가(변경 이력). 합격선: 사후 변경 0회, 있으면 이유 기록.
15. **결정 기록** [사람] 8절에 진행, 방향 전환, 중단 중 하나와 근거 절 링크, 다음 확인 날짜. 합격선: 셋 다 있음.
16. **지속 접점(운영 중인 제품)** [사람] 4절 날짜와 Q&A 로그로 최근 4주 고객 접점 횟수를 센다. 합격선: 4회 이상(주 1회).

기계 항목 1~8은 위 명령을 그대로 차례로 돌리고(새 스크립트 파일은 만들지 않아도 된다) 결과를 문서 끝 "검사 기록"에 붙인다. CI 작업에 같은 명령을 넣어 강제하면 A등급 조건을 채운다.

## 등급 판정

| 등급 | 조건 |
|---|---|
| A (최고 전문가) | 체크리스트 1~16 전부 통과. 기계 항목을 CI로 강제한다. 최근 4주 매주 고객 접점이 있고, 증거 없이 착수한 기능이 0건이다 |
| B (출시 가능) | 1~15 통과. 기계 항목은 손으로 돌렸고 결과를 문서 끝 "검사 기록"에 붙였다 |
| C (부채 있음) | 미달 항목(예: 인터뷰 2건뿐, 실험 미실행)이 8절 "남은 위험"과 부채 목록에 기록되어 있고, 결정이 "조건부 진행"으로 표시됐다 |
| D (위험) | 미달이 기록조차 없다. 또는 가상 인터뷰나 `[의견]`만으로 "검증됨"이라 썼다. 또는 실명, 연락처가 저장소에 있다 |

## 최고 전문가가 더 하는 것

1. **매주 만난다.** 프로젝트 시작에 한 번 몰아 하지 않고 매주 고객 접점을 일정에 박아 둔다(Torres 정의).
2. **인터뷰 직후 스냅숏을 쓴다.** 기억이 신선할 때 15~25분 안에 정리해서 인용을 잃지 않는다(Torres, 2024).
3. **아이디어를 말하지 않고 약속을 센다.** 칭찬은 버리고 시간, 소개, 돈 같은 약속을 진지함의 증거로 기록한다(Mom Test).
4. **기회 지도를 자주 고친다.** 인터뷰 3~4건마다 기회를 다시 묶고 대상 기회를 다시 고른다(Torres OST).
5. **해결책을 셋 놓고 비교한다.** 한 해결책에 정이 들기 전에 서로 다른 후보 3개를 같은 기준으로 견준다(Torres OST).
6. **합격선을 먼저 적는다.** 실험 전에 문턱값을 숫자로 적어 결과를 보고 해석을 바꾸지 못하게 한다(Test Card).
7. **기간 안에 가능한지 묻는다.** 기술 쪽 사람에게 "되나요" 대신 "2주 안에 되나요"를 묻고, 안 되면 no-go로 잘라 낸다(Shape Up 5장).
8. **설문이 있으면 수로 줄 세운다.** 중요도와 만족도를 물어 기회 공식으로 덜 채워진 필요를 고른다(Strategyn).

## 흔한 실패와 고치는 법

| 실패 | 왜 문제인가 | 고치는 법 |
|---|---|---|
| 아이디어를 설명하고 반응을 묻는다 | 상대는 예의로 칭찬하고, 칭찬은 증거가 아니다 | 아이디어를 꺼내지 않고 "지난번에 ~했을 때"를 묻는다 |
| "이런 거 있으면 쓰시겠어요?" | 사람은 미래 행동을 잘 예측하지 못한다 | 과거에 실제로 한 일, 쓴 돈과 시간을 묻는다 |
| AI가 만든 가상 인터뷰를 증거로 센다 | 우리 가정을 되비춘 것일 뿐이다 | `[가정]`으로 내리고 실제 3명 인터뷰나 기존 기록(문의, 리뷰)부터 본다 |
| 기회가 해결책의 다른 이름이다("알림 기능이 필요하다") | 해결책 하나에 갇혀 비교를 못 한다 | 고객 말로 다시 쓴다("약 먹을 시간을 자주 놓친다") |
| 해결책 하나로 예/아니오만 본다 | 더 싼 해결책을 놓친다 | 후보 3개를 같은 가정 표에 놓는다 |
| 합격선 없는 실험 | 어떤 결과든 성공으로 읽힌다 | 실험 카드에 숫자 합격선과 기한을 먼저 쓴다 |
| 이미 아는 쉬운 가정만 검증한다 | 진짜 위험은 그대로 남는다 | 중요도와 증거로 배치하고 오른쪽 위부터 |
| 지인과 가족만 인터뷰한다 | 대상 고객이 아니거나 듣기 좋은 말만 한다 | 고객 정의(상황, 최근 행동)로 모집하고 지인은 따로 표시한다 |
| 노트에 실명, 전화번호를 그대로 둔다 | 공개 저장소면 개인정보가 새어 나간다 | 익명 ID(I-01)로 바꾸고 원본은 저장소 밖에 둔다 |
| 결정 없이 조사만 계속한다 | discovery가 끝나지 않는 연구가 된다 | 1절 결정 질문에 날짜를 붙이고 8절에서 닫는다 |

# 채널 규칙, 일정, UTM

절차 7단계(채널 패키지)와 9단계(측정 계획)에서 채널 초안을 쓰고 링크를 만들 때 연다.

채널 규칙은 바뀐다. 아래는 2026-10-16에 원문을 열어 확인한 내용이다. 게시 직전에 각 원문을 다시 열어 바뀐 곳이 없는지 본다.

## 2. Show GN (GeekNews)

원천: https://news.hada.io/blog/show (2021-08-17 공지), https://news.hada.io/guidelines

올릴 수 있는 것:

- 본인이나 소속 조직이 만든 서비스, 제품, 앱, 오픈소스, 도구. 직접 만들었거나 제작에 참여했다고 밝힌다.
- 다른 사람이 지금 써 볼 수 있는 것. 완성도가 높을 필요는 없다. 하드웨어는 상세 설명 페이지, 책은 샘플 챕터가 있어야 한다.
- 가능하면 가입이나 이메일 입력 없이 바로 써 볼 수 있게 한다.

올릴 수 없는 것: 블로그 글, 가입이나 사전 예약 페이지, 뉴스레터, 목록형 글, YouTube 링크.

하지 않는 것: 지인에게 upvote나 댓글 부탁, 같은 설명을 댓글로 다시 올리기, 여러 계정으로 반복 등록. 같은 프로젝트는 일정 기간 안에 다시 올릴 수 없다(기간 수치는 원문에 없다).

초안 틀:

```markdown
제목: <서비스명> - <핵심 기능 한 구절>   (타입을 Show로 고르면 "Show GN:"이 자동으로 붙는다)

<무엇인지 1~2문장>
<누가, 어떻게 쓰는지>
<기존 방식과 무엇이 다른지>
<왜 만들었는지 2~3문장>
<받고 싶은 피드백 1~2개>
제가 만들었습니다. <체험 링크, UTM 포함>
```

## 3. 디스콰이엇 (disquiet.io)

- 한국 메이커 커뮤니티다. 제품마다 `/products/<이름>` 페이지가 있고, 메이커가 진행 상황을 글로 남긴다.
- 공식 게시 규칙 문서는 2026-10-16에 찾지 못했다(확인 못 함). 올리기 전에 사이트 공지와 안내를 확인하고, 확인한 내용을 런치 문서에 적는다.
- 초안은 Show GN과 같은 뼈대(무엇, 누구, 차이, 왜, 피드백)를 쓰고, 만드는 과정의 기록(무엇을 배웠나)을 한 단락 더한다.

## 4. Product Hunt

원천: https://www.producthunt.com/launch , https://www.producthunt.com/launch/preparing-for-launch

| 항목 | 규칙 |
|---|---|
| 이름 | 제품 이름만. 설명이나 이모지를 붙이지 않는다(공식 이름의 일부면 예외) |
| 태그라인 | 60자 이하. 꾸밈이나 과장 없이 담백하게 |
| 설명 | 500자 이하. 가치 제안과 핵심 기능 |
| 갤러리 | 이미지 2장 이상 필요, 권장 1270x760, GIF 가능 |
| 썸네일 | 필수, 정사각, 권장 240x240, 3MB 미만. GIF는 자동 재생되지 않으니 첫 장면만으로 뜻이 통하게 |
| 영상 | 선택, YouTube 링크만, 비공개 불가 |
| 태그 | 런치 태그 최대 3개 |
| 공동 제작자 | 런치 당일보다 훨씬 전에 만든 Product Hunt 계정이 있어야 한다 |
| 프로모 코드 | 쓰면 혜택, 코드, 만료일 모두 필요 |
| 첫 댓글 | 권장. 핵심 기능, 대상 사용자, 만든 이야기, 런치 혜택. upvote가 아니라 피드백을 부탁한다 |
| 예약 | 최대 한 달 전부터. 제약이 없으면 태평양 시간 0시 1분이 권장된다(한국 시간 기준 서머타임 기간 16시 1분, 그 밖 17시 1분) |
| 홍보 | 링크 공유는 자유. 사람들에게 직접 upvote를 부탁하면 안 된다. 방문해서 댓글을 남겨 달라고 부탁한다 |

## 5. 쓰레드, 유튜브, 블로그

- 글은 `gotekie-blog-writer` 스킬이 쓴다. 이 스킬은 런치 브리프, 주장 장부, 채널별 UTM 링크를 넘긴다.
- 채널의 글자 수 제한 같은 수치는 게시 직전에 그 채널의 공식 도움말로 확인한다. 이 파일은 수치를 고정하지 않는다.
- 대가를 받은 협업 글이면 `references/claims-and-law.md`의 표시 규칙을 함께 넘긴다.

## 6. UTM 규칙

GA4는 `utm_source`, `utm_medium`, `utm_campaign` 세 가지를 항상 쓰라고 하고, 값의 대소문자를 구분한다(`google`과 `Google`은 다른 값). 빠지면 보고서에 (not set)이 남는다. 그래서 값을 아래 표로 고정하고, 링크는 이 표에서만 복사한다.

| 매개변수 | 규칙 (하네스 기본값) | 예 |
|---|---|---|
| `utm_source` | 채널 이름, 소문자, 공백 없음 | `geeknews`, `disquiet`, `producthunt`, `threads`, `youtube`, `blog`, `newsletter` |
| `utm_medium` | 유입 종류, 소문자 | `community`, `social`, `video`, `email`, `referral` |
| `utm_campaign` | `launch-<슬러그>-<YYYYMM>` | `launch-memo-202610` |
| `utm_content` | 같은 채널 안에서 링크 위치 구분 | `first-comment`, `post-body`, `profile` |
| `utm_id` | 선택. 광고 플랫폼과 연결할 때만 | `lc-001` |

링크 예: `https://example.com/?utm_source=producthunt&utm_medium=community&utm_campaign=launch-memo-202610&utm_content=first-comment`

검사: 런치 문서의 링크 표에서 `rg -n 'utm_[a-z_]+=[^&\s]*[A-Z]'` 결과가 0건이어야 한다(대문자 값 찾기). 세 매개변수가 모두 있는지는 `rg -c 'utm_source=.*utm_medium=.*utm_campaign='`로 링크 수와 같은지 본다.

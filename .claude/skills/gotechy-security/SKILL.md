# /gotechy-security — 보안 리뷰

## 절차

1. **범위 결정** — 인자가 없으면 `git diff` 기준 최근 변경분. "전체"라고 하면 저장소 전체 (API·auth·db 영역 우선).
2. **감사 위임** — security-auditor 에이전트(읽기 전용)에게 범위와 함께 위임한다. 기준 문서: `docs/SECURITY.md` 체크리스트 + 위협 모델.
3. **정적 확인 병행** — 해당되는 경우:
   - `npm audit` (심각 취약점 확인)
   - 시크릿 스캔: 코드에 하드코딩된 키·토큰 패턴 grep
   - 새로 추가된 공개 엔드포인트의 인가·레이트 리밋 확인
4. **판정** — 발견 사항을 심각도로 분류:
   - 🔴 즉시 수정 (머지·출시 차단) — 시크릿 노출, 인젝션, 인가 누락
   - 🟡 이번 주 내 수정 — 방어 깊이 부족
   - 🟢 개선 권장 — tech-debt-tracker 기록
5. **위협 모델 갱신** — 새 공격 표면이 생겼으면 docs/SECURITY.md의 위협 모델 표에 행을 추가한다.

## 보고 형식

발견 항목별: 위치(`파일:줄`) / 시나리오(공격자가 어떻게 악용하나) / 수정 방법. 🔴이 있으면 수정까지 완료한 뒤 재검사한다.

## 주의

- 보안 이슈는 tech-debt-tracker로 미루지 않는다 (🟢 제외).
- 서드파티 스킬·의존성 추가 시 공급망 검토를 잊지 않는다.

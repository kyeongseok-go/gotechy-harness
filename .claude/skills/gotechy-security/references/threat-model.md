# 위협 모델 템플릿과 갱신 규칙

사용자 프로젝트에 `docs/security/threat-model.md`를 처음 만들거나, 새 진입 표면이 생겨 행을 더할 때 연다.

## 쓰는 법

- 뼈대는 Threat Modeling Manifesto의 네 질문이다: 무엇을 만들고 있나, 무엇이 잘못될 수 있나, 그래서 무엇을 하나, 충분히 잘했나. https://www.threatmodelingmanifesto.org/
- "무엇이 잘못될 수 있나"는 STRIDE 여섯 분류로 빠짐없이 묻는다: 위장(Spoofing), 변조(Tampering), 부인(Repudiation), 정보 노출(Information Disclosure), 서비스 거부(Denial of Service), 권한 상승(Elevation of Privilege). https://learn.microsoft.com/en-us/azure/security/develop/threat-modeling-tool-threats
- 완벽한 그림보다 쓸모 있는 표가 낫다. Manifesto가 경계하는 안티패턴은 혼자 다 하는 영웅, 문제 감상, 한 곳만 깊게 파기, 완벽한 표현이다.
- 행마다 "남은 것"을 쓴다. 완화가 없는 위협은 지우지 않고 남은 위험으로 둔다.

## 갱신 규칙

다음 중 하나가 생기면 같은 변경 안에서 행을 더하거나 고친다.

- 새 엔드포인트, 새 외부 입력(웹훅, 파일 업로드, 이메일 수신)
- 새 외부 서비스 호출, 새 SaaS로 데이터 전송
- LLM에 넘기는 새 콘텐츠 출처, 에이전트의 새 도구나 권한
- 새 비밀값, 새 역할이나 권한 단계
- 보안 리뷰에서 높음이나 중간 발견

## 템플릿 (복사해서 채운다)

```markdown
---
title: 위협 모델
updated: YYYY-MM-DD
asvs_target: L2   # 이유를 아래 한 줄로
---

# 위협 모델

목표 수준: L2. 이유: (예: 회원 이메일과 결제 내역을 저장한다)

## 1. 무엇을 만들고 있나

- 한 줄 설명:
- 데이터 흐름 (텍스트로 충분하다): 브라우저, API 서버, DB, 외부 서비스(결제, 메일, LLM API) 사이에 무엇이 오가나
- 신뢰 경계: 사용자 기기와 서버 사이, 서버와 외부 서비스 사이, 에이전트와 그 에이전트가 읽는 콘텐츠 사이

## 2. 자산

| 자산 | 왜 중요한가 | 어디에 있나 |
|---|---|---|
| 회원 개인정보 | 유출 시 법적 통지 의무, 신뢰 상실 | DB users 테이블 |
| 세션과 API 토큰 | 탈취 시 계정 장악 | 쿠키, 서버 비밀 저장소 |

## 3. 행위자

| 행위자 | 능력 | 동기 |
|---|---|---|
| 외부 공격자 | 공개 엔드포인트에 임의 요청 | 데이터 탈취, 무료 사용 |
| 다른 정상 사용자 | 자기 계정으로 로그인한 요청 | 남의 데이터 보기 |
| 오염된 콘텐츠 | 에이전트나 LLM이 읽는 파일, 웹, 이메일 안의 지시문 | 도구 오용, 데이터 반출 |
| 공급망 | 의존성, CI action, 플러그인, MCP 서버 | 설치 시점 코드 실행 |
| 내부 실수 | 개발자나 리드 에이전트의 잘못된 명령 | 없음(사고) |

## 4. 위협과 완화

| ID | 자산 | STRIDE | 진입 표면 | 위협 (공격자가 X를 하면 Y) | 완화 | 검증 | 남은 것 |
|---|---|---|---|---|---|---|---|
| T1 | 회원 개인정보 | 정보 노출 | `GET /api/orders/:id` | 다른 사용자의 주문 ID로 요청하면 남의 주소를 본다 | 쿼리에 소유자 조건 | A1 테스트 | 없음 |
| T2 | API 토큰 | 정보 노출 | LLM 요약 기능 | 문서 속 지시문이 도구로 토큰을 보내게 한다 | 도구 허용 목록, 발송은 승인 | G1, G4 테스트 | 모델 판단 오류 |

## 5. 충분히 잘했나

- 마지막 리뷰: docs/security/reviews/YYYY-MM-DD-<슬러그>.md
- 아직 모델에 없는 표면:
- 다음에 다시 볼 때:
```

## 에이전트를 쓰는 프로젝트에서 빠뜨리기 쉬운 행위자

- 저장소 내용이나 웹에서 읽은 지시로 오염된 작업 에이전트와 그 에이전트가 쓴 코드(테스트 실행 때 오너 권한으로 돈다)
- 오너와 같은 OS 사용자로 도는 다른 프로세스(키 파일, 설정 파일을 바꿀 수 있다)
- 내려받는 도구, 스킬, 플러그인의 공급망
- 결정을 대신 내리거나 force push, 배포를 하는 리드 에이전트의 실수

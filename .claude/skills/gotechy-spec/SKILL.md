# /gotechy-spec — 아이디어 → 스펙

## 공통 절차

0. **착수 판정** — `docs/PRODUCT_SENSE.md` '기능 추가 판단 체크' 4문항 + "지금 백로그 대비 이걸 먼저 할 이유" 3줄을 산출물 §0에 기록. 답하지 못하면 index.md에 '아이디어' 상태로만 등록하고 종료.
1. **트랙 판정** (판정 결과를 먼저 알리고 진행):
   - **미니 스펙** — 1일 미만 작은 기능: `_template-prd.md`의 §1 불편함 + §2 한 줄 정의·Non-goals + §3 성공 기준 1개. 리뷰 생략 가능.
   - **풀 스펙** — 기능 단위: `_template-prd.md` 전체 → `docs/product-specs/<기능-슬러그>.md`. 불편함 인터뷰는 최대 3문항(누가/언제/없으면 곤란한가), 성공 기준은 측정 방법·시점·실패 판정선까지 표로.
   - **위저드** — 제품·사이트 단위 (화면 여러 개, 신규 프로젝트): 아래 위저드 모드.
   - career_signals 대상이거나 사용자 데이터·인증·결제를 건드리면 최소 풀 스펙.

## 위저드 모드 (docs/WIZARD.md가 헌법 — 반드시 먼저 읽는다)

`docs/product-specs/<슬러그>/`에 4개 문서를 **한 스테이지씩, 승인 락으로** 만든다. 매 턴 `[위저드 00-brief · 1/7]` 형식으로 위치를 밝힌다. 위저드 중에는 코드를 만들지 않는다.

| 스테이지 | 산출물 | 방법 |
|---|---|---|
| 00-brief (1/7) | `_wizard-templates/00-brief.md` 복사 | 열린 인터뷰 3문항(무엇/누구/**핵심 액션 1개** — 답은 스토리로 유도) → **Appetite·No-gos를 솔루션보다 먼저** 확정 → Relume 공식 한 단락 브리프 |
| 10-prd (2/7) | `_template-prd.md` 복사 | 브리프에서 도출. 목표 지표는 전→후 수치, 문제는 이해관계자별 분해, **사용자 역할 표** 추가 (20의 입력) |
| 20-features (3/7) | `_wizard-templates/20-features.md` | 요구사항>기능>상세 3계층, 수용 기준은 **EARS 형식만**, 9슬롯은 구현 전 7/9 권장 |
| 30-user-flow (4/7) | `_wizard-templates/30-user-flow.md` | **하드 게이트: 확정된 기능 1개 이상 필수.** 범위는 선택지로("핵심 여정만" 기본). mermaid + 페이지 노드 표 |

- **질문 엔진**: 스테이지당 최대 5문항, AskUserQuestion 선택지 2~4개+추천안+"왜 묻는지". 모르는 건 추측 말고 `[NEEDS CLARIFICATION: …]` 마커 — **확정 조건 = 마커 0**. 답변 즉시 문서 반영 + Q&A 로그.
- **락**: 스테이지 요약 제시 → 명시적 승인 전 다음 진행 금지. 수정은 diff 제시 → 재승인. 승인은 `## 확정 이력`에 기록.
- **되돌아가기**: 상류 수정 시 하류 문서에 `[SYNC NEEDED: …]` 삽입 후 명시적으로 갱신 제안.
- **`--quick`**: 승인 게이트 없이 4문서 일괄 초안 (마커는 남김).
- 4/7 완료 시: 화면이 있으면 **`/gotechy-design`**, 아니면 `/gotechy-plan` 안내.

## 공통 마무리 (풀 스펙·위저드)

2. **career_signals(hypothesis)** — `~/.claude/gotechy-career.yaml`(없으면 `docs/career.example.yaml`)의 jd_keywords 매칭, 가설만 기록 (evidence는 ship 시점).
3. **색인 갱신** — `docs/product-specs/index.md`에 행 추가 (상태·우선순위. 위저드는 폴더 링크로).
4. **적대적 리뷰** — spec-reviewer에게 위임 (위저드는 10-prd+20-features를 함께). 🟡/🟢은 반영 또는 기각 사유 기록. **🔴은 에이전트가 기각할 수 없다** — 반영하거나 지적 원문과 함께 사용자에게 이관 (판정 기준은 위임하지 않는다).
5. **확정 조건** — 🔴 0건 + `[NEEDS CLARIFICATION]` 0개. 확정 후 변경은 변경 이력에 기록, Non-goals 축소(스코프 확대)는 사용자 승인 필수.

## 완료 기준

- 트랙에 맞는 산출물 + 색인 갱신 + 리뷰 종결. 사용자에게 요약 3줄과 미해결 질문(마커 목록) 보고.

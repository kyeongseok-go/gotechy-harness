# 신뢰와 검색 기본

절차 1단계(재료표), 6단계(신뢰 검사), 7단계(검색 기본)에서 연다.

## 1. 재료표

글을 쓰기 전에 쓸 사실을 표로 모은다. 글의 숫자, 인용, 경험 문장은 모두 이 표의 한 줄과 이어져야 한다.

| # | 사실 | 출처 | 확인 |
|---|---|---|---|
| F1 | 검색 p95가 820ms에서 140ms로 줄었다 | ExecPlan Outcomes, 측정 명령 출력 | 직접 확인 |
| F2 | 공식 문서는 기본 타임아웃을 30초로 둔다 | 공식 문서 링크 | 문서 확인 |
| F3 | 다른 팀도 같은 문제를 겪었다 | 이슈 링크 | 추정(본문에 "~라는 이슈도 있어요"로만) |

- "직접 확인"은 이번에 명령을 돌리거나 화면을 본 것이다. "문서 확인"은 원문을 연 것이다. 나머지는 "추정"이고, 본문에서 단정하지 않는다.
- 경험 문장("써 봤어요", "3시간 걸렸어요")은 "직접 확인" 줄에만 쓴다. 해 보지 않은 것은 "공식 문서에 따르면", "아직 직접 써 보지는 못했지만"으로 쓴다.
- 재료표는 글 파일 맨 아래 HTML 주석으로 남긴다(`references/templates.md` 6절). 나중에 고칠 때 근거를 다시 찾지 않아도 된다.

## 2. 누가, 어떻게, 왜 (Google 사람 중심 콘텐츠)

Google의 사람 중심 콘텐츠 문서(최종 갱신 2026-10-05)는 글을 누가, 어떻게, 왜 만들었는지 스스로 점검하라고 한다.

- **누가**: 작성자를 밝힌다(`author: 고텍이`). 지어낸 작성자 소개나 AI로 만든 얼굴 사진을 사람 전문가처럼 쓰지 않는다. 문서가 이를 기만적인 작성자 표시의 예로 든다.
- **어떻게**: 독자가 "이거 AI가 쓴 거야?"라고 물을 만한 글이면 AI와 자동화 사용을 밝히는 것이 유용하다고 문서가 쓴다. 이 스킬은 모든 글 끝에 한 줄을 둔다(하네스 기본값): "이 글은 초안 작성에 AI(Claude)를 썼고, 사실과 수치와 코드는 고텍이가 직접 확인했어요."
- **왜**: 사람을 돕는 것이 첫째 목적이어야 한다. 검색 순위를 조작하려고 자동화를 쓰면 spam policies 위반이다.

E-E-A-T(경험, 전문성, 권위, 신뢰)는 Google이 직접적인 순위 요소가 아니라고 밝히고, 그중 신뢰가 가장 중요하다고 쓴다. 그래서 E-E-A-T를 "순위 올리는 기술"로 쓰지 않고, 직접 해 본 경험(삽질기)과 확인 가능한 출처로 신뢰를 쌓는 기준으로만 쓴다.

## 3. 출처 쓰는 법

- 글 끝에 "출처" 절을 둔다. 링크 글자는 문서 이름으로 쓴다("여기" 금지).
- 공식 문서, 표준, 원저자 글을 먼저 쓴다. 요약 블로그는 원문을 찾을 수 없을 때만.
- 버전이 있는 기술이면 버전과 확인 날짜를 적는다. 예: "Next.js 16.4 기준, 2026-10-16 확인".
- 발행 전에 링크가 열리는지 확인한다.

```bash
grep -oE 'https?://[^ )>"]+' docs/content/blog/2026-10-16-rag.md | sort -u | \
  while read -r u; do printf '%s %s\n' "$(curl -s -o /dev/null -w '%{http_code}' -L "$u")" "$u"; done
```

200이 아닌 줄은 고치거나 뺀다.

## 4. 협찬, 무료 제공, 제휴 링크 표시

원천: 추천ㆍ보증 등에 관한 표시ㆍ광고 심사지침(공정거래위원회예규 제499호, 시행 2026-06-01). 지침의 "유명인" 정의에 블로거가 들어 있다.

표시가 필요한 경우: 상품, 이용권, 할인, 원고료, 수수료(제휴 링크 포함)를 받았거나 받기로 하고 쓴 리뷰와 추천.

블로그 글의 표시 방법:

- 제목이나 글의 첫 부분에 둔다. 첫 부분이면 글자 크기나 굵기로 본문과 구분한다.
- 댓글, "더보기", 링크 뒤에 숨기지 않는다.
- 분명한 한국어로 쓴다. 지침이 적절하다고 든 예: "소정의 원고료를 지급받았지만, 저의 솔직한 후기입니다", "소정의 수수료를 지급받음", "대가성 광고", "#광고", "#협찬".
- 지침이 불충분하다고 든 예: "체험 후기", "체험단", "선물", 브랜드 해시태그만, "AD", "PR", "sp", "Sponsor" 같은 외국어 표기.
- 사진 위주 글이면 사진 안에, 해시태그면 첫 번째 해시태그에 둔다. 영상은 제목이나 영상 안에, 영상 전체가 추천이면 시작과 끝에 둔다.

이 스킬의 틀(하네스 기본값):

```markdown
> **광고 표시:** 이 글은 [회사]로부터 [무엇]을 받고 썼어요. 좋은 점과 아쉬운 점은 직접 써 본 그대로 적었어요.
```

frontmatter에 `sponsored: true`를 두고, 끝에 한 번 더 같은 내용을 짧게 쓴다.

## 5. 이미지

- 직접 찍은 화면과 직접 그린 그림을 먼저 쓴다.
- 남의 이미지는 사용 조건(라이선스)을 확인하고 출처를 적는다. 확인하지 못하면 쓰지 않는다.
- 화면 캡처에서 토큰, 이메일, 내부 주소, 개인정보를 가린다.
- alt는 무엇이 보이는지 문장으로 쓴다(WCAG 2.2 1.1.1). 예: `![로그인 화면에서 "구글로 계속하기" 버튼을 누르는 모습](...)`.

## 6. 검색 기본

Google SEO Starter Guide(최종 갱신 2025-12-10)와 spam policies(최종 갱신 2026-08-28)에서 블로그에 필요한 것만 옮겼다.

| 항목 | 기준 |
|---|---|
| 제목 | 페이지마다 다르고, 내용을 정확히 말한다. 40자 이내(하네스 기본값, Google은 길이 수치를 정하지 않는다) |
| description | 그 글만의 짧은 요약. 120자 이내(하네스 기본값) |
| URL 슬러그 | 내용을 알 수 있는 단어(`/blog/rag-basics`), 무작위 숫자 지양 |
| 소제목 | H1 1개, H2와 H3로 구조, 소제목이 내용을 말한다 |
| 이미지 | alt 100% |
| 링크 | 관련 글끼리 내부 링크. 링크 글자가 무엇으로 가는지 말한다 |
| 분량 | 목표 글자 수를 두지 않는다. Google은 선호하는 글자 수가 없다고 쓰고, 그런 믿음으로 분량을 맞추는 것을 경고 신호로 든다 |
| 키워드 | 같은 말을 순위용으로 반복하지 않는다(keyword stuffing은 spam policies 위반) |
| 날짜 | 내용을 실제로 고쳤을 때만 `updated`를 바꾸고 글 끝에 고친 내용을 적는다. 새것처럼 보이려고 날짜만 바꾸는 것은 Google 문서가 경고 신호로 든다 |
| 대량 생성 | AI로 가치 없는 글을 많이 만들지 않는다(scaled content abuse) |

AI 검색 답변에 인용되기 쉬운 모양도 사람에게 좋은 모양과 같다. 질문형 소제목 아래 첫 문장에 답을 쓰고, 수치와 출처와 짧은 인용을 붙인다. GEO 논문(Aggarwal 외, KDD 2024)의 실험에서 출처 인용, 통계 추가, 인용문 추가가 노출 지표를 가장 많이 올렸고, 쉬운 표현도 15~30% 범위의 개선을 보였다. 실험 조건이 실제 서비스와 다르므로 노출을 약속하는 근거로 쓰지 않는다.

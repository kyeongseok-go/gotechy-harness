# AI_PLAYBOOK.md — AI 적용 서비스 개발 플레이북

> AI를 기능·제품에 넣을 때 따르는 과정. 기반: 「AI를 다루는 엔지니어의 작업 규약」(개인 정리 아티팩트) + Anthropic/OpenAI 공식 가이드.
> 한 문장 요약: **AI를 잘 쓴다는 것은 프롬프트를 잘 쓴다는 뜻이 아니다. 문제를 정의하고, 컨텍스트를 설계하고, 검증 체계를 만들고, 에이전트를 지휘한다는 뜻이다.**

## 0. 4대 역량 루프 (모든 AI 작업의 뼈대)

```
① 문제 정의 → ② 컨텍스트 설계 → ③ 검증 설계 → ④ 오케스트레이션
        ↑                                              │
        └────────── 측정 결과가 문제 정의를 다시 고친다 ──┘
```

사람(고텍이)이 쥐는 것: **기준을 올리는 일, 거절하는 일, 마지막에 눈으로 보는 일.** 실행은 위임해도 판정 기준은 위임하지 않는다.

## 1. 문제 정의 — 구현보다 여기에 시간을 쓴다

- 잘못된 문제를 풀면 좋은 답도 틀린 답이다. **검증 대상 1순위는 산출물이 아니라 문제 그 자체** — 문제 후보를 여러 개 만들어 구현 전에 채점하고 상위만 구현한다.
- **AI 적합성 판단**을 먼저 통과시킨다:
  - [ ] 이 문제는 규칙 코드로 못 푸는가? (정규식·if문으로 풀리면 LLM 금지)
  - [ ] 오답의 비용은 얼마인가? 오답이 치명적이면 human-in-the-loop 또는 AI 배제.
  - [ ] "기술에서 찾으면 용도를 찾고, 문제·페인포인트에서 찾으면 서비스를 찾는다" — 출발점이 페인포인트인가?
- **스코핑은 에이전트 배율로**: "사람 기준 3~4주" 크기로 잡고 에이전트로 1~2일에 끝낸다는 전제로 간다. 시간 부족을 이유로 미리 좁히던 습관을 버린다 — 전수 탐색 후 사후 선택.

## 2. 컨텍스트 설계 — 프롬프트보다 앞선 단계

- "에이전트는 이미 충분히 똑똑하다. **재료가 안 좋으면 요리도 안 좋다. 이건 셰프의 문제가 아니다.**"
- 컨텍스트는 유한 자원(context rot): 목표에서 **역산**해 필요한 컨텍스트 목록을 먼저 적는다 — 요구사항 원문, 도메인 규약, 심사자(사용자)의 취향까지.
- **첫 프롬프트에 "네가 나를 인터뷰해라"**: 모자란 컨텍스트를 에이전트가 캐내게 한다. 인터뷰 결과는 SPEC으로 만들고 **구현은 새 세션**에서.
- LLM 기능의 컨텍스트 설계 순서: 시스템 지시(불변) → 도메인 지식(RAG/벤더링) → 사용자 입력(적대적 취급, 지시와 분리) → 출력 스키마(구조화 강제).

## 3. 검증 설계 — 채점기를 산출물보다 먼저 만든다

**"광범위한 문서를 쓰기 전에 평가를 만들어라"** (Anthropic 스킬 가이드). 순서: 빈틈 식별 → 평가 생성 → 기준선 확립 → 최소 지시문 → 반복.

### 검증 게이트 4레벨 (설정 비용 ↔ 내 주의력 트레이드)

| 레벨 | 방식 | 언제 |
|---|---|---|
| L1 | 프롬프트 안에서 — "테스트 돌리고 통과까지 고쳐" | 오늘 당장, 모든 작업 |
| L2 | 세션 목표 조건 — 별도 평가자가 매 턴 재확인 | 반나절 이상 작업 |
| L3 | 결정론적 게이트 — Stop hook이 통과 전 턴 종료를 막음 | 반복되는 필수 규칙 |
| L4 | 별도 심사자 — 신선한 컨텍스트의 모델이 결과를 반박 | 출시·머지 전 |

체크가 없으면 **내가 검증 루프가 된다** — "다 된 것 같다"가 유일한 신호가 되는 상태를 금지한다.

### LLM 기능의 eval 3축

1. **오프라인 eval** — 대표 질의·페르소나·시나리오를 미리 모아 일괄 실행. **20개로 시작한다**. 골든셋 형식·통과 기준·그레이더 규약은 **`docs/evals/README.md`**(집행 문서), 실행은 `npm run eval`.
2. **온라인 eval** — 실사용 궤적(trajectory) 분석: 시나리오 준수, 답변 품질, 턴 단위 상호작용, 속도.
3. **UXR** — 사용자 피드백 별도 축.

- LLM-as-judge는 항목별 0.0~1.0 루브릭 + critique 먼저 쓰고 판정 + **주기적으로 사람과 캘리브레이션**. 사람이 따로 본다 (judge는 정합성, 첫인상·취향은 사람).
- **트랜스크립트를 종교처럼 읽는다** — 0% 통과는 대개 에이전트 무능이 아니라 태스크/그레이더 결함 신호. 주 1회 사람이 직접 읽는다.
- **eval은 모델·프롬프트·하네스 변경의 게이트다** — 통과해야 승격. 100% 근접 시 회귀 스위트로 졸업, 새 난제 추가 (포화 관리).
- 채점자 격리 (blind reviewer) + bar는 실제보다 높게. 테스트는 데모 데이터가 아니라 **실 데이터**로.
- 비결정성 측정: 탐색 도구는 pass@k, 사용자 대면 신뢰성은 pass^k (k회 전부 성공).

## 4. 오케스트레이션 — 구조가 병렬을 만들고 병렬이 속도를 만든다

- **지휘와 실행 분리**: 방향·품질 판단은 메인 세션 한 곳(드리프트 방지), 실행은 서브에이전트, 평가는 블라인드 서브에이전트.
- **세션 분리 + 파일 인계**: 설계 세션 → `HANDOFF.md` 압축 → 새 세션에서 구현. 같은 정정을 두 번 했으면 세션이 오염된 것 — `/clear` 후 배운 것을 넣어 재시작.
- **복잡도는 증명될 때만**: 단순 프롬프트 → 평가로 최적화 → 부족할 때만 멀티에이전트. 멀티에이전트는 ~15배 토큰 — 그 값을 하는지 잰다.
- 스캐폴딩(리서치 템플릿·심사 스킬)은 끝나도 남는 **자산**으로 만든다 → `.claude/skills/`.

## 5. LLM 기능 구현 규범 (코드 레벨)

- **모든 LLM 호출은 검증 관문을 지난다**: 출력 스키마(구조화) 강제 → 형식 검증 → 실패 시 1회 재질의 → 템플릿 폴백. 명확한 규칙은 코드가 검사하고, 애매한 판단만 AI에게.
- **프롬프트는 코드다**: `prompts/` 디렉터리에 파일로 버전 관리 (`prompts/_template-prompt.md` 규약 — version·changelog·연결 eval), 변경 시 eval 통과 게이트.
- **가드레일**: 사용자 입력은 시스템 지시와 분리(인젝션 방어), 고위험 행동(파괴·과금·발송)은 human-in-the-loop 승인 게이트를 **구조로** 강제 — 절차(SOP)는 건너뛸 수 있지만 구조는 승인 없이 다음 단계가 실행되지 않는다.
- **관측 (1인 개발 최소 스택)**: 모든 LLM 호출을 자체 래퍼로 감싸 JSONL 1줄 로깅(`{ts, model, prompt_ver, in_tok, out_tok, cost_usd, latency_ms, ok, fallback}`) → 주 1회 `npm run llm:report`가 총비용·실패율·p95를 `docs/generated/llm-cost.md`(러너 연결 후 생성)로 집계. 트래픽이 생기면 Langfuse/Helicone 승격(ADR 1건). 성과 기준에 **토큰 비용 포함** — 엔진이 좋아도 운영 ROI가 안 맞으면 중단된다.
- **장기(멀티 세션) 작업**: 첫 세션은 프레임워크 구축 — 테스트를 구조화 포맷으로 먼저, 셋업 스크립트, ExecPlan Progress 유지. 이후 세션은 compaction보다 **새 컨텍스트 + 파일에서 상태 재발견**(Progress·git log 검토 후 시작). 항상 커밋된 깨끗한 상태 유지.
- **인간 개입 트리거 2가지**: 실패 임계 초과(재시도 한도) / 고위험 행동 (OpenAI 에이전트 가이드).
- 모델 선택: 최신·최강을 기본으로 시작 → eval로 다운그레이드 여지 확인 (비용 최적화는 동작 확인 후).

## 6. 완료의 정의 (AI 기능 전용 — /gotechy-ship에 추가되는 게이트)

- [ ] 오프라인 eval 셋(최소 20개) 존재 + 통과 기준 명시
- [ ] LLM 호출 전부에 스키마 검증 + 폴백 존재
- [ ] 프롬프트가 저장소에 버전 관리됨
- [ ] 고위험 행동에 승인 게이트(구조) 존재
- [ ] 토큰 비용/1회 호출 측정치 기록
- [ ] "기준은 내가 정하고 실행을 시켰다"로 설명 가능한 상태 (판정 기준의 소유)

## 금지 문장 (마인드셋 가드레일)

- ~~"AI에게 검증해달라고 했습니다"~~ → **"기준은 제가 정했고, 계산(실행)을 시켰습니다."**
- ~~"AI가 저보다 잘 짜서"~~ → **"코딩 속도로는 AI를 못 이깁니다. 다만 무엇이 진짜 문제인지 정하는 것과 결과 판정은 제 몫입니다."**
- ~~"토큰을 이만큼 썼습니다"~~ → 성과는 **같은 자원으로 더 많은 아웃풋**. 안 되면 프록시 메트릭(10시간→1시간)을 직접 만든다.

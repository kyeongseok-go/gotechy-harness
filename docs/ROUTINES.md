# ROUTINES.md — 개발 루틴과 프롬프팅 루틴

> 고텍이의 반복 가능한 작업 리듬. 의지가 아니라 루틴이 완주를 만든다 (50% 증후군 방어의 행동 버전).

## A. 기능 하나의 루틴 (표준 궤도)

```
1. /gotechy-spec "아이디어"        ← 미니/풀/위저드 트랙 (제품 단위면 Brief→PRD→기능→플로우)
1-b. /gotechy-design               ← 화면 있는 제품: 사이트맵→와이어프레임→스타일가이드
2. (스펙 리뷰 반영)                ← spec-reviewer 왕복 1회
3. /gotechy-plan 스펙파일          ← ExecPlan + tracer bullet 마일스톤
4. 새 세션에서 구현 시작            ← 계획 세션과 분리 (컨텍스트 청결)
5. 마일스톤마다: 테스트 → Progress 체크 → Surprises 기록
6. /gotechy-security               ← 인증·API·DB 건드렸으면 필수
7. /gotechy-ship                   ← 완료 게이트 (통과까지 반복, 소재 기록까지)
8. /gotechy-launch                 ← 콘텐츠 생성의 유일한 진입점 (블로그·쓰레드·유튜브)
```

## B. 프롬프팅 루틴 (세션을 여는 법)

### B-1. 큰 작업의 첫 프롬프트 템플릿

```
[목표] <완성되면 무엇이 달라지는지 한 문장>
[컨텍스트] @docs/product-specs/<스펙>.md, @docs/exec-plans/active/<계획>.md
[제약] AGENTS.md 헌법 준수. 완료 기준은 Validation 섹션.
[지시] 시작 전에 부족한 정보를 나에게 인터뷰해라. 질문이 없으면 계획을 요약하고 M1부터 시작해라.
```

핵심 3요소: **역산된 목표 + 컨텍스트 경로 + "네가 나를 인터뷰해라"**.

### B-2. 세션 위생 규칙

- 같은 정정을 **두 번** 했으면 세션이 오염된 것 → `/clear` 후 배운 것을 첫 프롬프트에 넣고 재시작.
- 설계와 구현은 **다른 세션** — 설계 결정은 HANDOFF(ExecPlan의 Context 섹션)로 압축해 넘긴다.
- 넓은 탐색은 서브에이전트(Explore)로 위임 — 메인 컨텍스트에 파일 덤프를 쌓지 않는다.
- 같은 프롬프트를 **세 번** 붙여넣었으면 스킬로 만든다. 같은 실수가 **두 번** 반복되면 rules/hook으로 만든다.

### B-3. 지시의 강도 사다리

요청(프롬프트) → 규약(CLAUDE.md/rules) → 강제(hook/린터/구조 테스트). "매번 예외 없이 지켜져야 한다"면 무조건 오른쪽으로.

## C. 하루 루틴 (개인 표준)

| 시점 | 행동 | 목적 |
|---|---|---|
| 세션 시작 | active ExecPlan의 Progress 확인 → 오늘의 마일스톤 1개 선언 | 방향 고정 |
| 작업 중 | 발견 즉시 Surprises 기록 (미루면 증발) | 콘텐츠 재료 축적 |
| 세션 끝 | Progress 체크 + 다음 세션 첫 명령을 한 줄 남김 | 재개 비용 제로화 |
| 주 1회 | doc-gardener 실행 + tech-debt 상환 1건 + `npm run llm:report`(LLM 비용 집계) | 부패 방지·비용 가시화 |
| 분기 1회 | DB 백업 복원 리허설 (docs/RELIABILITY.md) | 복원 안 해본 백업은 백업이 아니다 |
| 프로젝트 완료 | /gotechy-ship → /gotechy-launch → 위키 ingest | 3종 출력 완성 |

## D. 검증 루틴 (레벨을 올리는 순서)

1. 모든 작업: 프롬프트에 "테스트 돌리고 통과까지 고쳐" (L1)
2. 반나절 이상: ExecPlan Validation을 세션 목표로 (L2)
3. 반복 규칙: hook으로 승격 (L3)
4. 머지·출시 전: 블라인드 심사자 — spec-reviewer/security-auditor/Codex 교차 검증 (L4)
5. **마지막은 사람**: 산출물을 직접 열어본다. "이걸 본 사용자가 느낄 감정을 내가 대신 느껴본다." 에이전트 루프는 정합성을 잡고, 첫인상과 집요함은 사람이 잡는다.

## E. 판정 문장 루틴 (말버릇 교정)

작업 보고·회고·면접에서 쓰는 문형:
- "기준은 제가 정했고, 실행을 시켰습니다."
- "확신이 아니라 비교 데이터로 결정했습니다."
- "이 규칙은 문장이 아니라 hook으로 강제했습니다."
- 기각에도 사유를 남긴다: 수용 / 수정 수용 / 기각(사유) — 리뷰 18건이면 18건 전부 종결 상태가 있어야 한다.

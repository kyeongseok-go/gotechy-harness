# 0005. 오너 결정 서명: HMAC과 원천에서 계산한 필수 게이트

- 상태: 승인됨 (1a 범위). 서명 방식(HMAC)은 2026-10-14 1b N1에서 [0006](0006-owner-auth-secure-enclave.md)으로 대체
- 날짜: 2026-10-14
- 관련: [계약 6절, 9절](../references/contract.md), [1a ExecPlan Decision Log](../exec-plans/active/2026-10-13-harness-v2-phase1.md), [밤샘 보고](../references/evidence/2026-10-14-overnight/README.md)

## 맥락

하네스에서 사람의 일은 결정이다. 결정이 평범한 텍스트 파일이면 손으로 고치거나, 낡은 결과에 대한 결정을 새 결과에 쓰거나, 다른 프로젝트의 결정을 가져와도 알 수 없다. 워커는 오너와 같은 OS 사용자로 돌기 때문에, 같은 사용자 안에서 쓰는 비밀 키로는 악의적인 프로세스의 자가 승인까지 막을 수 없다(교차 검토 두 모델이 독립적으로 같은 지적).

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. HMAC-SHA256 서명 + 결정 순간의 맥락 고정 + 위협 모델을 정직하게 축소 (선택) | 구현이 작고 검증이 빠르다. 실수, 낡은 판본, 손 편집, 다른 프로젝트 재사용을 막는다 | 같은 OS 사용자의 악의적 프로세스는 못 막는다 |
| B. 공개키 서명 + 키를 macOS 키체인에(생체 인증) | 같은 사용자 프로세스도 키 사용에 사람 확인이 필요하다 | 1a 범위를 넘는다. 플랫폼 의존 |
| C. 별도 OS 사용자나 원격 결정 서버 | 가장 강한 분리 | 설치와 운영 부담 |

## 결정

A를 1a에 쓰고, B나 C는 1b에서 검토한다.

- 서명 대상: 프로젝트 id, 작업과 게이트 번호, class, 질문, 선택지, HANDOFF 판본, 되돌리기 어려움, 작업 명세 요약값(status 제외), HANDOFF 해시, 선택, 다음 지시, 키 id, nonce, 시각.
- 필요한 게이트는 게이트 파일 목록이 아니라 원천(작업 명세, 현재 HANDOFF)에서 계산하고, 빠지면 다시 연다. 읽을 수 없는 게이트 파일이 있으면 모든 실행을 멈춘다(fail-closed).
- 워커 코드가 키에 닿지 않게: verify를 macOS `sandbox-exec` 안에서 돌리고(키 폴더와 private 읽기 금지, 작업 폴더 밖 쓰기 금지), 워커의 심볼릭 링크를 거부한다.
- 결정은 대화형 터미널에서만 받는다. 실수를 막는 장치이고 의도적 우회는 막지 못한다고 계약에 적는다.

## 결과 (Consequences)

- 쉬워지는 것: `run`과 `accept`가 결정을 믿을 수 있는지 기계로 판정한다. 공격 시나리오가 테스트로 고정돼 있다(`tests/e2e/decide.test.ts`, `hardening.test.ts`). 방어 코드를 하나씩 빼는 mutation check 30종(1차 구현 11, 감사 1차 수정 10, 2차 수정 9)을 모두 테스트가 잡았다.
- 어려워지는 것: 키 교체(`keys rotate`) 뒤에는 열려 있는 모든 결정을 다시 해야 한다. 결정 장부는 private이라 다른 컴퓨터로 옮기면 검증이 실패한다.
- 남은 한계: Codex 워커는 키 파일을 읽을 수 있다. 결정 장부에 서명이 없다. 같은 사용자의 자가 승인. 모두 계약 6.3절 "알려진 한계"에 적고 1b ExecPlan에서 다룬다.

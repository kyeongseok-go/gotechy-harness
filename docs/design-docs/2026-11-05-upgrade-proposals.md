# 오너가 정할 업그레이드 6가지

업그레이드 루프(U0~U9)는 오너 결정이나 유료 실행 없이 할 수 있는 일만 했다. 아래는 그 선을 넘는 일이다. 새 공급망 의존성(도구 교체, 새 바이너리), 유료 실행, 또는 일하는 방식이 바뀌는 일이라 오너가 고른다. 결정마다 추천과 그 근거, 하지 않으면 생기는 일, 되돌리는 법을 적었다.

순서는 추천하는 처리 순서다. 1번이 가장 먼저다. 근거 자료는 `docs/references/research/2026-11-05-harness-sota-research.md`(출처와 날짜 포함)다.

## 1. 첫 실전 프로젝트를 먼저 시작할까 (T-008, 다른 모든 것보다 먼저)

- **추천: 예.** 이번 루프의 가장 큰 발견은 "3주 동안 아무도 돌리지 않아 테스트 11개가 깨진 채였다"는 것이다(U0). 하네스를 실제로 쓰지 않으면 규칙이 낡아도 모른다. 2단계 계획(phase2)도 "써 봐야 무엇을 고칠지 안다"고 적었다.
- 아래 2~6번은 첫 프로젝트에서 실제로 필요해질 때 하는 편이 낫다. 미리 하면 하네스 만들기가 일이 되는 함정에 다시 빠진다(설계 문서 11절).
- 오너가 할 일: 만들고 싶은 제품을 한 문장으로 말하기. 그러면 `gotechy-discover`나 `gotechy-spec`부터 시작한다.

## 2. 이 브랜치(upgrade-2026-11)를 harness-v2에 합칠까

- **추천: 합친다.** 바뀐 것은 모두 테스트로 증명했고 CI가 초록이다. 특히 U0(한글 파일 이름 버그), U2(가드가 시간 초과면 통과하던 것), U7(무시 경로에 심은 파일이 verify에 닿던 것)은 실제 위험을 줄인다.
- 주의할 점 하나: train이 2026.11.0으로 바뀐다. 합친 뒤 다른 폴더(예: 원래 저장소 폴더)에서 처음 실행할 때는 shim이 아니라 `bin/gotechy`(부트스트랩)나 mise 실행 파일로 먼저 깔아야 한다(TD-032, 이번 루프의 사고). 이 Mac mini에는 이미 깔려 있다.
- 되돌리는 법: 합친 커밋을 되돌리면 train도 2026.10.0으로 돌아간다. 옛 판 도구는 지우지 않아 그대로 있다.

## 3. 팩 평가를 유료로 처음 돌릴까 (2단계 P3)

- **추천: 예산 5달러로 한 번, 두 단계로.**
  1. 무료에 가까운 점검: 케이스 하나를 `--runs 1 --ablation none`으로 돌려 플러그인을 찾는지 본다. 조사에서 이 저장소에 `.claude-plugin/plugin.json`이 없어 "스킬 있음과 없음" 비교(Δ)가 안 나올 수 있다는 점을 찾았다(추정, 실행으로 확인 필요).
  2. 본 실행: 15개 팩의 케이스를 `--ablation with-without --runs 3 --max-cost-usd 5 --json`으로. 채점은 결정적 채점기(`tool_used: Skill`, 정규식)를 먼저 믿고, LLM 채점기는 사람 라벨 20개로 맞춰 본 뒤에 믿는다.
- 하지 않으면: 전문가 팩 15개가 실제로 도움이 되는지 모른다. 판정표 R1이 2단계(동작)에 머문다. 연구 보도(SkillsBench, 2차 자료)는 "남이 다듬은 스킬은 평균 +16점, 스스로 만든 스킬은 이득 없음"이라 적는다. 우리 팩이 어느 쪽인지 재 볼 가치가 있다.
- 비용 주의: `--max-cost-usd`는 추정에 대한 상한이고 이미 시작한 실행은 끝까지 돈다. 5달러를 조금 넘을 수 있다.

## 4. 리눅스 verify 샌드박스로 srt를 쓸까 (TD-009, TD-025)

- **추천: 지금은 보류. 리눅스에서 워커를 돌릴 일이 생기면 한다.** 지금 verify 샌드박스는 macOS(sandbox-exec)에서만 격리하고 리눅스에서는 기록만 남긴다. 오너는 Mac에서만 워커를 돌리므로 당장 구멍은 없다.
- 할 때의 안: Anthropic의 sandbox-runtime(srt, v0.0.81, 리눅스는 bubblewrap과 seccomp)으로 리눅스 갈래만 더한다. macOS는 지금 구현을 유지한다(실험으로 쌓은 Seatbelt 규칙을 잃지 않게). 먼저 "bun test가 srt 안에서 도는지" 실험한다. Codex도 리눅스에서 같은 bubblewrap을 쓴다.
- 위험: srt는 아직 0.0.x 베타이고 Ubuntu 24.04 이상은 AppArmor 설정이 필요하다. 새 바이너리를 train에 넣는 공급망 결정이다.

## 5. 비밀 값 검사를 gitleaks에서 Betterleaks로 바꿀까

- **추천: 지금은 바꾸지 않고, 3개월 뒤(2026-02) radar로 다시 본다.** gitleaks 8.30.1은 2026-03 뒤로 새 판이 없지만 저장소는 살아 있다(마지막 커밋 2026-10-23).
- Betterleaks 1.10.0(2026-11-04, gitleaks 원작자가 새로 시작, MIT)의 장점: 하네스가 실험으로 찾아 코드로 막은 두 위험(대상 폴더의 `.gitleaks.toml`이 검사를 끄는 것, 저장소 git 설정 실행)을 도구 기본값으로 막는다. 체크섬에 sigstore 서명이 있다.
- 바꾸지 않는 이유: 프로젝트가 8개월 됐고 v2.0이 아직 rc라 규칙 집합이 흔들릴 수 있다. 하네스는 이미 두 위험을 코드로 막았다(TD-012). 바꿀 때의 판정 기준은 `tests/e2e/accept-secrets.test.ts`가 그대로 통과하는지다.

## 6. codex 워커에 토큰 상한을 걸까 (TD-015)

- **추천: codex 워커를 계속 쓰기로 정할 때만(T-008의 두 번째 결정), 그리고 두 겹으로.** codex에는 달러 상한이 없고 시간 상한만 있다. 0.166에 `features.rollout_budget`(토큰 상한)이 있지만 개발 중이고 기본으로 꺼져 있다.
- 두 겹: (a) 하네스가 `--json` 이벤트의 사용량을 더해 상한에서 프로세스를 끝낸다(무료로 녹화 테스트 가능, 바닥 방어). (b) `features.rollout_budget`을 덧댄다(키가 바뀔 수 있어 실제 실행으로 확인 필요, 유료).
- codex 워커를 쓰지 않기로 하면 이 일은 필요 없다.

## 이번 루프가 하지 않은 작은 후보 (결정은 필요 없고, 첫 프로젝트에서 필요할 때)

- mise를 2026.11.0으로 올리고 shim 고리 버그가 고쳐졌는지 실험(TD-032). 부트스트랩 체크섬이 바뀌어 train 갱신과 함께 한다.
- CI에 `skills-ref validate`(Agent Skills 표준 검증기, 표준이 2026-10-22 Linux Foundation 산하 AAIF로 이관)와 `zizmor`(워크플로 정적 검사).
- `bunfig.toml`에 `minimumReleaseAge = "3d"`(새 의존성 공급망 방어, Bun 1.4.4).
- radar가 찾은 새 판 6건(uv, OpenTelemetry 두 건, Stryker, Keep a Changelog, spec-kit)을 팩 references에 반영. 스킬 본문은 오너 결정, references 사실 갱신은 eval 통과가 조건이다(D6).

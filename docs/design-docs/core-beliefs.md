# core-beliefs.md — 에이전트 우선 운영 원칙

> 이 저장소에서 사람과 에이전트가 일하는 방식의 헌법. 다른 문서와 충돌하면 이 문서가 이긴다.

## 1. Humans steer. Agents execute.

사람(고텍이)의 역할은 방향 설정·취향 판단·최종 승인. 에이전트의 역할은 조사·구현·검증·문서화. 사람이 코드를 직접 짜는 것은 예외 상황이다 — 그 예외가 반복되면 하네스의 결함으로 보고 하네스를 고친다.

## 2. 에이전트가 볼 수 없는 것은 존재하지 않는다

채팅·머릿속·Slack·노션에만 있는 결정은 다음 세션에서 증발한다. 모든 결정·맥락·발견은 저장소의 md로 인코딩한다. "나중에 정리"는 없다 — 발생한 그 자리에서 기록한다.

## 3. 완료는 증명이다

"됐어요"가 아니라 "이 명령을 치면 이 출력이 나온다"가 완료다. 검증할 수 없는 완료 선언은 미완료로 취급한다. 50% 마무리 증후군의 해독제는 의지가 아니라 **구조(작은 마일스톤 + 완료 게이트)**다.

## 4. 지도는 짧게, 진실은 깊게 (Progressive Disclosure)

진입 문서(AGENTS.md/CLAUDE.md)는 지도만. 상세는 필요할 때 로드되는 문서·rules·skills로. 컨텍스트는 유한한 예산이다 — 고신호 토큰만 남긴다.

## 5. 권고와 강제를 구분한다

- 어기면 아쉬운 것 → 문서(권고)
- 어기면 안 되는 것 → hook·린터·구조 테스트(기계 강제)
- 린트 에러 메시지에는 교정 방법을 넣는다 (에러가 곧 에이전트 교육이다)

## 6. 모든 프로젝트는 3종 출력으로 완성된다

①동작하는 제품 ②커리어 시그널(채용 경쟁력) ③콘텐츠 재료(블로그·위키 내재화). 하나라도 비면 프로젝트의 가치가 새는 것이다. 이것이 이 하네스가 일반 하네스와 다른 이유다.

## 7. 부채는 매일 소액 상환

기술 부채·문서 부패는 고금리 대출이다. doc-gardener와 tech-debt-tracker로 상시 관리하고, 금요일 몰아서 청소하지 않는다.

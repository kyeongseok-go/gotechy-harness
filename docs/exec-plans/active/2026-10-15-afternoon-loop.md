# 오후 자율 실행 루프

오너(고텍이)가 외출하며 "다음 할 일을 찾아 가능한 만큼 진행"을 맡겼다(2026-10-15 13:52). 리드(Claude Code, Opus 5.5)가 혼자 진행한다. 방식은 밤샘 루프 2(`2026-10-15-overnight-loop.md`)와 같다. 시작 시각은 이 파일의 커밋 시각이다.

## 목표

1b 중 오너 없이 할 수 있는 일을 진행한다. 오늘 오너가 직접 겪은 문제(결정 끝난 작업이 "결정 필요"로 보임)를 먼저 고친다. 오너가 돌아오면 공문서 프로젝트를 바로 시작할 수 있게 사전 조사와 첫 질문 목록을 준비한다(T-005 기본값 "Touch ID 확인 뒤 바로 시작").

## 마일스톤마다 도는 루프

계약 먼저, 실패하는 수용 테스트, 구현, `bun run check`, mutation check, 적대적 리뷰, 기록(ExecPlan, HANDOFF), 커밋과 harness-v2 푸시, `gh run watch`로 CI 확인. CI가 실패하면 다음 일 전에 고친다. 대기열을 건너뛸 때는 이유를 이 문서에 적는다.

## 멈춤 규칙

- 같은 문제로 3번 실패하면 그 일을 멈추고 이유를 적은 뒤, 의존하지 않는 다음 일로 넘어간다.
- 오너만 정할 수 있는 결정은 되돌릴 수 있는 기본값으로 진행하고 커밋을 따로 나눈다. 보고의 "확인 필수"에 올린다.

## 하지 않는 것

- `~/.claude`, `~/.codex` 설정 수정, `gotechy setup` 실행(오늘 낮에 오너 지시로 적용한 것 외에 더 바꾸지 않는다)
- 리드가 `gotechy keys`, `decide`, `serve`, `loop`를 실행하는 것, 확인 창(Touch ID나 맥 암호) 띄우기, 실제 `~/.gotechy` 아래 생성이나 수정. 테스트의 보안 칩 테스트는 사람 확인 없는 테스트용 키를 임시 폴더에만 만든다(창 없음)
- force push, 외부 발행, 위키 적재, 배포
- 실제 Claude나 Codex 워커, 감사관, Orca 워커를 부르는 유료 실행
- 서브에이전트가 `bin/gotechy`나 설치 명령을 실제 HOME으로 실행하는 것. 서브에이전트 지시에 금지 목록을 반드시 적는다

시작 때 상태(13:54): `~/.claude/settings.json` sha256 앞 8자리 `d5a1327f`, `~/.codex/config.toml` `9028eee7`(오너의 codex 사용으로 바뀔 수 있음), `~/.gotechy` 파일 전체 해시 `ac4c41f4`(backup 2개, bin 2개, githooks 2개, owner의 active, heads 4개, 키 blob과 pub).

## Validation and Acceptance

1. F1~F7의 각 항목은 완료 판정을 통과했거나, 멈춘 이유와 다음 단계가 이 문서에 있다.
2. 끝낸 마일스톤마다 `bun run check`가 통과한 커밋이 harness-v2에 있고, 그 커밋의 CI가 성공이다.
3. "하지 않는 것"에 적은 일이 일어나지 않았다. 끝날 때 위 해시를 다시 확인한다.

## 순서를 바꾼 것 (14:25)

- F4(프로젝트 hook)는 워커가 `--restricted`라 프로젝트 hook이 걸리지 않고, 실제 동작은 유료 실행 없이 확인할 수 없어 미뤘다. 같은 목적(저장 직후 lint)은 TD-016(lint 실패 시 다시 쓰기)이 하네스 쪽에서 이루지만 run 핵심 흐름 개편이라 크다.
- 그래서 오너 가치와 확인 가능성 순으로 바꿨다: F6 중 TD-020(작고 보안), 감사 12차 반영, 공문서 준비, 화면 시안(Validation 13), 시간이 남으면 TD-019, TD-016, F5(Orca).

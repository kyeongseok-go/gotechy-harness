# 3초 카드와 읽기 전용 화면 (M2b)

## 한 줄로

여러 워커의 HANDOFF를 "결정 필요, 실패, 완료" 순서의 카드로 보여 주는 `gotechy inbox`와, 같은 내용을 브라우저로 보는 `gotechy render`를 만들었어요. 워커가 악의적인 글을 써도 화면에서 실행되지 않게 막았어요.

## 읽기 3단

- 3초: 카드 한 장. 막는 결정 수, 검증 결과, 리스크 수, 비용, 바뀐 파일 수.
- 30초: 한 줄 요약, 결정 필요, 한 일, 리스크(펼쳐 둠).
- 3분: 증거, 새 용어, 말해 보기, 다음 단계, 리드 측정값(접어 둠).

## 없는 것을 없다고 단정하지 않기

실제 HANDOFF로 써 보다가 버그를 찾았어요. 옛 형식 HANDOFF라 리스크 절을 찾지 못했는데, 카드에는 "리스크 없음"이라고 나왔어요. 실제 리스크는 2건이었어요. 그래서 절이 없으면 "리스크 기록 없음", 계약을 어기면 "형식 오류 N건"으로 보여 주게 했어요. 비용을 모르면 "$0.00"이 아니라 "비용 모름"이에요.

## 화면 보안: 두 겹

1. escape: 파일에서 읽은 모든 글을 화면에 넣기 직전에 글자로 바꿔요. `<script>`는 태그가 아니라 글자로 보여요. Markdown은 원시 HTML을 허용하지 않는 설정으로만 바꾸고, 링크는 http(s)만, 이미지는 만들지 않아요.
2. CSP: 혹시 escape에 구멍이 생겨도, 브라우저가 "이 화면은 스크립트를 실행하지 않는다"는 규칙을 보고 막아요.

테스트는 악성 HANDOFF를 실제로 렌더한 뒤, 결과를 HTML 파서로 읽어 스크립트, 이벤트 속성, 허용 목록 밖 요소가 하나도 없는지 세요.

## 터미널도 공격면이에요

악성 HANDOFF가 요약에 터미널 제어 문자(ESC)를 넣으면 인박스 출력에서 앞줄을 덮어쓰거나 글자를 숨길 수 있어요. 양방향 제어 문자로 글자 순서를 뒤바꿔 보이게 할 수도 있어요(Trojan Source). 그래서 인박스와 화면 모두에서 이런 문자를 지우고, HANDOFF lint도 이런 문자를 오류로 막아요.

## 새 용어

- golden test: 정답 출력을 파일로 고정해 두고 실제 출력과 한 글자까지 비교하는 테스트예요.
- CSP: 웹 화면이 무엇을 불러오고 실행할 수 있는지 브라우저에 알려 주는 규칙이에요.
- Trojan Source: 보이지 않는 문자로 글이나 코드가 실제와 다르게 보이게 하는 공격이에요.

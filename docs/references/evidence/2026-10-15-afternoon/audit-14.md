# 보안 감사 14차

대상은 HANDOFF 형식 오류 때 워커가 HANDOFF만 다시 쓰는 기능(TD-016)이에요. 결과는 높음 0, 중간 5, 낮음 7이에요. 다시 쓰기에서 추적 파일 쪽으로 HANDOFF 밖 변경을 숨겨 브랜치에 넣는 길은 없었어요. verify를 다시 돌리지 않는 것도 안전하다는 판정이에요(브랜치에는 검증한 tree에 HANDOFF만 더해짐).

| 번호 | 지적 | 처리 |
|---|---|---|
| 중간 1 | 다시 쓰기가 성공하면 워커가 만든 무시 파일(예: `.codex/hooks.json`)이 worktree에 남아요 | 고침. HANDOFF 글만 읽고 작업 트리를 직전 커밋으로 통째로 되돌려요 |
| 중간 2 | 비밀 값 검사는 워커 원문을 보는데, 기록되는 것은 YAML을 다시 직렬화한 글이에요. `"sk-..."`처럼 숨긴 키가 살아나요 | 고침. 실험으로 확인한 뒤, 기록할 글을 키 모양과 로그인 값으로 검사해요. 걸리면 워커 HANDOFF를 버리고 실패. 첫 실행도 같아요 |
| 중간 3 | 다시 쓰기 중 예외가 나면 작업이 running으로 남고 기록이 어긋나요 | 고침. 예외를 잡아 실패로 끝맺고, 되돌리기는 결과를 돌려줘요(실패하면 git을 더 부르지 않음) |
| 중간 4 | 막힌 다시 쓰기의 비용이 빠지고, 루프 예약이 다시 쓰기를 몰라요 | 고침. 모든 결과의 사용량을 더하고, 루프는 다시 쓰기 비용까지 예약하며, 비용을 모르면 예약값으로 세요. codex는 한 번만 다시 써요 |
| 중간 5 | 워커가 남긴 백그라운드 프로세스가 검사 뒤에 git 설정을 바꿀 수 있어요(추정) | TD-029(실험 먼저). 첫 실행에도 있던 문제예요 |
| 낮음 1 | verify가 실패해도 다시 쓰게 했어요 | 고침 |
| 낮음 2 | 오류 메시지에 섞인 워커 글이 지시문에 그대로 들어가요 | 고침. 한 줄로 펴고 제어 문자를 지우고, 20건과 8KB 상한 |
| 낮음 3 | 다시 쓰기 기록이 남지 않고 `verified.at`이 다시 쓴 시각으로 바뀌어요 | 고침. `run.end`에 `rewrites`, `rewrite_blocked`. lead_note에 다시 쓰기 사유를 합침. verify 시각은 한 번만 |
| 낮음 4 | 다시 쓰기 중 변조로 끝나면 기록끼리 어긋나요 | 일부. 변조 끝맺음 이벤트에 사용량을 남겨요. 문구 정리는 그대로 |
| 낮음 5 | 스냅샷에 worktree의 `HEAD`가 없어요 | 고침. 바뀌면 되돌리고 실패 |
| 낮음 6 | 워커의 직접 커밋 이력이 남아요 | 다시 쓰기는 직전 커밋으로 되돌려 해결. 첫 실행은 그대로(기존 동작) |
| 낮음 7 | 테스트 공백 | 무시 파일, 숨긴 키, 비용 합, verify 실패, 지시문 정리, 이벤트, HEAD 테스트를 더했어요 |

## mutation 점검

고친 방어 7종을 하나씩 빼 봤고 모두 테스트가 잡았어요.

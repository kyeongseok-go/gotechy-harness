# HANDOFF 화면 시안 비교

같은 HANDOFF(`sample-handoff.md`, 공문 마감일 추출 작업, 막는 결정 2, 기본값 1, 감사 지적 1)를 세 가지로 그렸어요. 화면 크기는 폰(375x844)과 넓은 화면(1280) 두 가지예요. A는 지금 렌더러(`renderHandoffPage`, serve 모드)의 실제 출력이고, B와 C는 같은 스타일 위에 손으로 만든 시안이에요.

| 시안 | 폰 | 넓은 화면 |
|---|---|---|
| A. 지금 화면 | `a-phone.png` | `a-desktop.png` |
| B. 결정 카드 먼저 | `b-phone.png` | `b-desktop.png` |
| C. 주장과 증거 대조 | `c-phone.png` | `c-desktop.png` |

## 판정 기준

스펙의 성공 기준(오너가 HANDOFF 한 건을 이해하고 결정하는 데 3분 이내)에서 나온 다섯 가지로 봤어요. 판정은 스크린샷을 보고 리드가 했어요. 오너가 실제로 써 보고 잰 값은 아니에요.

| 기준 | A. 지금 | B. 결정 카드 먼저 | C. 주장과 증거 대조 |
|---|---|---|---|
| 폰 첫 화면에 결정에 필요한 것(선택지, 추천, 이유)이 다 있나 | 아니요. 질문과 추천만 있고 선택지와 이유는 아래 | 예. 첫 결정은 선택지 버튼, 추천, 이유가 다 보임 | 아니요. A와 같음 |
| 같은 내용이 두 번 나오나 | 예. "결정하기"와 "결정 필요"에 같은 질문 | 아니요 | 일부. 결정 자세히를 접어 둠 |
| 감사 지적이 보이나 | 아니요. 화면에 감사 결과가 없음 | 예. 상태 칩과 "감사관이 본 것" 절 | 예. 틀린 주장 바로 옆에 붙어 가장 잘 보임 |
| 주장의 사실 표시(확인, 추론)가 눈에 띄나 | 글 끝의 [확인] 글자 | 색 있는 작은 표 | 표의 한 칸 |
| 지금 렌더러에서 바꿀 양 | 없음 | 중간. 결정마다 선택지와 이유를 카드로, 상태 칩, 감사 절 | 큼. 한 일과 증거, 감사 지적을 항목별로 짝지어야 함(지금은 자유 글) |

## 리드 제안

**B를 기본으로 하고, "한 일" 절만 C의 대조표 방식(주장 옆에 감사 지적)으로 바꾸는 것**을 추천해요.

- 이유 1: 오너가 할 일은 결정이에요. B는 폰 첫 화면에서 바로 고를 수 있어요.
- 이유 2: C의 장점은 틀린 주장 옆에 지적이 붙는 것이에요. 이 예시처럼 감사 지적(연도 규칙이 코드와 다름)이 결정 G-004와 이어질 때, B만으로는 결정 전에 지적을 놓칠 수 있어요.
- 이유 3: C를 통째로 쓰려면 워커가 "한 일"마다 증거를 짝지어 써야 해서 HANDOFF 계약을 바꿔야 해요. 감사 지적은 `file:line`이 있어서 "한 일" 항목과 짝짓기가 상대적으로 쉬워요.

## 오너가 정할 것

1. 위 제안대로 갈지, A(그대로), B만, C만 중 무엇으로 갈지 정해요.
2. B의 선택지 버튼을 누르면 곧바로 그 선택으로 결정 화면(이해 문항과 확인 창)을 열지 정해요. 지금 serve는 게이트 화면에서 다시 고르게 돼 있어요.

## 한계

- B와 C는 정적 시안이라 실제 serve 화면의 제출 흐름은 없어요.
- 판정은 한 사람(리드)의 눈으로 했고, 예시 HANDOFF 하나만 썼어요. 결정이 없는 완료 작업이나 실패 작업 화면은 비교하지 않았어요.

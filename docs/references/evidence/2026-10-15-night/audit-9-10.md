# 보안 감사 9차(N3 loop)와 10차(N4 guard) (2026-10-15 새벽, 밤샘 루프 2)

둘 다 읽기 전용 security-auditor에게 맡긴 적대적 리뷰예요. 높음은 둘 다 0건이에요.

## 9차: `gotechy loop` (높음 0, 중간 5, 낮음 5)

| 등급 | 지적 | 처리 |
|---|---|---|
| 중간 1 | 루프 상태와 보고서가 커밋된 링크를 따라 저장소 밖에 씀 | `.gotechy` 아래 폴더를 모두 링크 검사, 상태는 임시 파일과 rename, 보고서는 새 파일로만 |
| 중간 2 | 계약 폴더 안의 파일(HANDOFF, 명세)이 링크면 따라가 씀 | 프로젝트 명령이 그 폴더 안의 링크 파일도 거부 |
| 중간 3 | 파일 이름과 다른 명세 id로 검사와 실행 대상이 갈림 | id가 다르면 돌리지 않음 |
| 중간 4 | Codex는 비용 상한이 없어 최악 비용 계산이 틀림 | 루프가 Codex 작업을 돌리지 않음(TD-015 갚기 전) |
| 중간 5 | 워커가 적은 `lead_note`로 실패 판정을 조종 | 워커의 `lead_note`를 버림, 실패 표시는 리드가 잰 값만 |
| 낮음 | 최소 예약, 루프 잠금과 예산 상한, 예외 처리, 상태 검증, 보고서 마크다운 | 모두 반영 |

## 10차: `gotechy guard` (높음 0, 중간 6, 낮음 8)

| 등급 | 지적 | 처리 |
|---|---|---|
| 중간 1 | 주석, here-doc, 줄 이어 쓰기, 백슬래시를 셸과 다르게 읽어 뒤 명령을 놓침 | 셸처럼 읽는 판정기로 다시 씀. 닫히지 않은 문법은 막음 |
| 중간 2 | 예약어, 묶음, 감싸는 명령의 옵션 값, xargs, timeout, find -exec | 모두 벗겨서 판정 |
| 중간 3 | `npx wrangler deploy` 같은 러너 경유 배포와 전역 옵션 뒤 발행 | 러너와 전역 옵션을 벗기고 배포 목록을 넓힘 |
| 중간 4 | hook이 2가 아닌 코드로 끝나면 명령이 그대로 실행됨 | 래퍼가 가드 실패를 exit 2로, 가드는 어떤 오류든 막음 |
| 중간 5 | settings.local.json이 이미 있으면 가드가 조용히 안 깔림 | 다른 키는 지키고 hook만 더함, 경로 갱신 |
| 중간 6 | `keys rotate`에 Touch ID도 TTY 검사도 없음 | keys init과 rotate는 대화형 터미널에서만 |
| 낮음 | 셸 옵션 묶음, 입력 형식, 표준 입력 기한, 오탐, 위키, 이름 대소문자, 상태 줄 링크, 경로 인용 | 모두 반영. 일부러 숨긴 형태는 계약 12절에 한계로 적음 |

## 검증

- 테스트: `tests/e2e/loop.test.ts`(감사 9차 묶음 포함 19개), `tests/core/guard-audit10.test.ts`, `tests/e2e/guard-cli.test.ts`.
- mutation check: 9차 8종, 10차 7종을 모두 잡음(처음 살아남은 1종은 "주석에 it's가 있는 평범한 명령" 허용 테스트를 더해 잡음).
- 감사관이 실측을 부탁한 것 중 하지 않은 것: Claude Code가 hook의 exit 1이나 시간 초과 때 실제로 명령을 실행하는지, 가드 지연 시간. 이 맥의 전역 설정을 바꾸지 않는 규칙 때문에 hook을 실제로 걸어 보지 않았어요.

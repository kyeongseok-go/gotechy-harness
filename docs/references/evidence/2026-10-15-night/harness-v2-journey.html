왜 이렇게 정했나

결정이유버린 대안
기록은 저장소 파일에 두고, 도구는 실행만 해요.도구를 바꿔도 기록이 그대로예요. 확인 ADR 0003 하나에 의존(회사 PC처럼 Orca가 없으면 멈춰요), 다른 실행 도구 추가(유지 비용)
결정은 키로 서명해요.같은 계정의 AI가 비밀 값 파일을 읽고 오너인 척할 수 있었어요. 확인 ADR 0006 (오너 확인 전 제안)파일 비밀 키(1a 방식, 같은 계정 프로그램이 읽어요), 맥 키체인(같은 사용자 앱이 꺼낼 수 있어요), 보안 키 기기(사야 하고 늘 꽂아야 해요)
검증은 프로젝트의 로 해요.이 맥의 키만 바꿔서는 결정을 만들 수 없고, 고정 파일을 바꾸면 기록에 드러나요. 확인 contract.md 6.3절이 맥의 현재 키로 검증(바꿔치기를 못 잡아요)
지문 창에 를 넣어요.게이트 번호만으로는 내 결정의 창인지 알기 어려워요. 확인 감사 8차번호와 선택만 표시
팩은 공개 저장소의 커밋에 고정해요.커밋은 바뀌지 않고, 따로 올릴 이름표가 필요 없어요. 확인 ADR 0002이름표(태그), 내 컴퓨터 경로, 도구별 복사(변조 검사를 직접 만들어야 해요), 실시간 배포 서버(주요 도구가 아직 지원 안 해요)
무인 루프는 시도마다 최소 비용을 미리 잡아 예산을 계산해요.비용 한도를 걸 수 없는 워커나 아주 작은 예산 값으로 예산을 피하지 못하게 해요. 확인 1b 계획 결정 기록실제 비용만으로 계산

확인 필수: 오너가 해야 할 것

답은 리드에게 번호와 선택지로 알려 주세요(원문은 orchestration/handoffs/T-005.md). 막는 결정은 답해야 다음 일이 움직여요. 기본값은 이미 그 값으로 진행했어요.

1번이 먼저예요. 화면을 푼 채 터미널 앱의 저장소 폴더에서 치세요.

sh scripts/owner-touchid-check.sh

이 맥에 실제 오너 키를 만들고, 시험 프로젝트의 같은 질문 두 개를 터미널에서 진짜 지문으로 결정해요. G-001은 지문으로 승인하고, G-002는 지문 창에서 취소해요. 끝의 검증 출력이 G-001 ok, G-002 pending이고 장부 줄 수가 1이면 통과예요. 끝에 안내하는 화면 서버로 화면 결정도 해 봐요(선택). 처음이면 도구를 내려받아요.

할 일선택지추천과 이유

내 말로 설명해 보기

30초 안에, 하네스 v2가 무엇이고 지금 어디까지 왔는지 설명해 보세요.

AI 워커에게 같은 형식으로 일을 맡기고, 보고서를 읽고, 오너가 지문으로 서명한 결정만 다음 일로 잇는 도구예요. 맡기고 읽는 뼈대는 실제 워커로 돌았어요. 지문 결정은 테스트 도구로만 확인했고, 분야별 전문가 팩과 자동 최신화는 아직 설계뿐이에요.

흔한 오답 "전문가 라이브러리가 완성됐다"는 틀려요. 팩은 보고 형식 하나뿐이에요.

결정을 지문으로 서명하게 바꾼 이유는 뭘까요?

AI 워커가 오너와 같은 맥 계정에서 돌아서, 서명에 쓰던 비밀 값 파일을 읽고 오너인 척 결정할 수 있었어요. 키를 보안 칩 안에 두고 서명마다 지문을 거치게 하면, 오너 손 없이는 서명이 나오지 않아요. 키를 바꿔치기하는 길은 프로젝트에 고정한 키로 막아요.

흔한 오답 "비밀 값을 더 깊은 폴더에 숨겼다"는 틀려요. 파일로 있는 한 같은 계정 프로그램은 읽을 수 있어요.

화면에서 결정할 때, 오너가 본 것과 서명하는 것이 같다는 것을 어떻게 지킬까요?

화면을 그릴 때 게이트, 작업 명세, 보고서를 묶은 값을 함께 보내고, 서명 직전에 다시 계산해 다르면 거부해요. 지문 창에는 화면과 같은 확인 코드가 보여요. 다른 사이트의 요청은 출처 검사와 위조 방지 값이 막아요.

흔한 오답 "지문만 대면 안전하다"는 틀려요. 지문은 키를 쓰는 것만 허락할 뿐, 무엇에 서명하는지는 보여 주지 않아요.

아직 확인하지 못한 것과 그 이유는?

진짜 지문 서명은 오너가 기기 앞에 있어야 해요. 실제 워커로 무인 루프를 돌리는 일은 유료 실행이라 밤 계획에서 하지 않기로 했어요. 분야별 전문가 팩(R1)은 다음 단계 일이에요.

흔한 오답 "테스트가 다 통과했으니 지문도 된다"는 틀려요. 테스트는 같은 명령을 흉내 내는 가짜 서명 도구로 돌았어요.

# 전문가 팩 검토 기록

팩 15개(스킬)는 조사 에이전트 7개가 나눠 썼어요. 리드가 공통 지시(파일 구성, 문체, 사실 규칙, 금지 사항)를 주고, 쓴 뒤에 독립 검토 두 가지를 돌렸어요.

## 1. 교차 검토 (spec-reviewer, 이음매)

스킬 하나하나의 수준은 높았지만 스킬 사이의 약속이 어긋났어요. 20건을 찾았고, 리드가 기준을 정해 수정 에이전트가 고쳤어요.

| 지적 | 처리 |
|---|---|
| 작업 크기 문턱이 스킬 넷에서 서로 다름(계획이 필요한 기준) | 크기 표 하나를 spec, plan, build, ship에 같은 글로 넣고 테스트가 같음을 검사 |
| 미니 스펙은 확정할 수 없음(풀 스펙 항목까지 검사) | 해당 항목에 "(풀, 위저드)" 적용 범위 표시 |
| comply-kr 결과를 읽는 게이트가 없음 | ship bar에 법 요구 검사, spec과 plan의 넘기기에 comply-kr, ai-eval 조건 |
| 부채 표 형식 둘, 심각도 어휘 셋 | ship의 표 하나로 맞추고 표시 사이 글이 같음을 테스트 |
| ADR 틀 둘 | retro의 틀로 맞추고 같음을 테스트 |
| [기계] 항목에 도구가 없음 | 줄마다 `도구:`를 적게 하고 테스트로 검사 |
| 기본값 표지가 다섯 가지 | "(하네스 기본값)" 하나로 |
| 게이트 명령과 CI를 만드는 스킬이 없음 | plan 첫 마일스톤에 넣고 ship에 CI 틀 |
| 그 밖 12건(위저드 순서, 커버리지 기본값, 트리거 겹침 등) | 반영 |

수정 에이전트가 남긴 "언제 ADR로 올리나" 기준(plan, retro, build에서 조금씩 다름)은 리드가 하나로 합쳐 같은 글로 넣고 이음매 테스트에 더했어요.

## 2. 사실 표본 검증 (조사 에이전트, 원문 대조)

10개 스킬에서 30건을 골라 원문(법제처 본문, GitHub 릴리스, 표준 기구 페이지)과 대조했어요.

- 맞음 28, 틀림 1(Ruff 판 0.17.0, 실제 0.17.1, 고침), 원문에서 확인 안 됨 1(처리방침 작성지침 2026.4 개정의 생성형 AI 부록, "보도 기준"으로 표시).
- 근거 표기 보강 3건(OpenTelemetry 판의 근거 주소, ISO 25000-23.2 이름, 디자인 대비값의 버림 표기)도 반영했어요.
- 표 밖에서 20여 건을 더 봤고 모두 맞았어요.

## 3. 기계 검사

`tests/core/packs-structure.test.ts`가 스킬마다 구조(SKILL.md 길이, bar와 렌즈, 출처 형식, 평가 케이스 형식과 채점기 키), 자기 완결(하네스 문서를 가리키지 않음), 문체 경고 0건, 스킬 사이 이음매(크기 표, 부채 표, ADR 틀, ADR 기준이 같음, 있는 스킬 이름만, [기계] 항목의 도구, 기본값 표지 하나), 이 저장소의 `.claude/skills` 사본이 원본과 같음을 검사해요.

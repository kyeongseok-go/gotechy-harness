PASS if 응답이 아래를 모두 만족한다.
- 채점기를 만들기 전에 베타 로그를 사람이 직접 읽는 오류 분석(라벨, 메모, 실패 유형 분류)을 먼저 하라고 했다.
- 성공 기준을 정확도, 안전이나 거절, 지연, 비용 중 3개 이상 차원에서 숫자로 제시했다.
- 골든셋을 실제 실패에서 시작하고(예: 20개 안팎), 거절해야 하거나 행동하지 말아야 하는 케이스를 포함하며, 튜닝에 쓰지 않는 test 분할을 두라고 했다.
- 규칙으로 판정되는 것은 코드 채점기로, 판단이 필요한 것은 LLM judge로 나누고, judge를 사람 라벨과 비교해(TPR, TNR 또는 일치도) 검증하라고 했다.
- 환불 API 호출을 코드 수준의 승인 단계나 금액 상한으로 막으라고 했고, 프롬프트 인젝션(검색 문서 경유 포함) 케이스를 넣으라고 했다.
- 프롬프트나 모델 변경 때 eval을 회귀 게이트로 돌리라고 했다.

FAIL if 아래 중 하나라도 해당한다.
- ROUGE, BLEU, "도움됨 1~10점" 같은 범용 점수를 주 지표로 권했다.
- LLM judge를 사람 라벨과 비교하지 않고 그대로 쓰라고 했다.
- 환불 안전장치를 시스템 프롬프트 문장으로만 해결했다.
- 합격선이 숫자 없이 끝난다.

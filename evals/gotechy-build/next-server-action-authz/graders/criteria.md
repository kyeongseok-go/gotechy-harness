bar 항목 T1~T3(테스트 우선), B1(경계 파싱), V5(보안 연결)와 stack-react-next의 Server Actions 보안 규칙을 본다.

PASS if 아래를 모두 만족한다.
1. 액션 함수 안에서 직접 세션을 확인하고, 로그인하지 않았으면 삭제 없이 거부한다. 페이지에서 한 확인이 액션을 보호하지 않는다는 점을 말하거나 코드로 보여 준다.
2. 글의 `authorId`와 현재 사용자 ID가 같은지(또는 명시한 관리자 권한) 확인한 뒤에만 삭제한다.
3. 글 ID 같은 입력을 스키마(Zod, Valibot 등)로 파싱한 뒤 쓴다.
4. 구현 코드보다 테스트를 먼저 제시하고, 테스트에 "로그인 안 함", "다른 사람의 글", "잘못된 입력" 가운데 두 경우 이상이 들어 있다.
5. 삭제 뒤 캐시 갱신 수단(`updateTag`, 인자 두 개인 `revalidateTag`, `revalidatePath` 중 하나)을 쓴다.

FAIL if 아래 중 하나라도 해당한다.
- 소유권 확인 없이 로그인 여부만으로 삭제한다.
- 페이지, 레이아웃, `proxy.ts`나 미들웨어의 확인만 믿고 액션 안에서 확인하지 않는다.
- 테스트가 없거나, 구현을 다 쓴 뒤 형식적으로 붙이고 실패 확인 단계가 없다.
- 입력을 `as string` 같은 단언으로만 받는다.

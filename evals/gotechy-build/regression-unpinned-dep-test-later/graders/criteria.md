bar 항목 T1~T3(테스트 우선), D1, D2, D4, D7(의존성), B1(경계 파싱)을 본다.

PASS if 아래를 모두 만족한다.
1. 구현 코드보다 실패하는 테스트(`bun test`용)를 먼저 제시하고, 테스트를 미루자는 요청을 그대로 따르지 않는 이유를 한두 문장으로 밝힌다.
2. 새 의존성을 넣는다면 정확한 버전으로 고정한다(`bun add --exact dayjs@<버전>`이나 `"dayjs": "<버전>"`처럼 범위 기호 없이). lockfile(`bun.lock`)을 같은 변경에 넣으라고 한다. 또는 표준 기능(`Date`, `Intl`, `Temporal`)으로 충분하다며 의존성을 넣지 않는다.
3. 의존성을 넣는다면 유지보수 활동, 라이선스, 취약점 확인이나 ADR, 결정 필요 항목 중 하나 이상을 언급한다.
4. 입력 문자열을 경계에서 파싱해 잘못된 날짜(예: "2026-13-45", 빈 문자열)를 명시적 오류로 처리한다.
5. 기준 시각과 시간대를 다룬다(현재 시각을 인자로 받거나 테스트에서 고정한다).

FAIL if 아래 중 하나라도 해당한다.
- `bun add dayjs`, `npm install dayjs`, `dayjs@latest`, `"^1.11.0"` 같은 범위 버전을 그대로 권한다.
- 테스트 없이 구현만 준다.
- 테스트를 구현 뒤에 덧붙이기만 하고 실패를 먼저 확인하는 단계가 없다.

bar 체크리스트 E18~E21(RPO와 RTO, 마지막 백업 시각, 90일 안 복원 리허설과 검증, 보존과 PITR)과 흔한 실패 "백업이 있다고 가정함"을 본다.

PASS if 아래를 모두 만족한다.
1. 복원을 해 본 적 없는 백업은 통과로 세지 않는다고 말하고, 이 항목을 미통과(또는 부채 기록)로 둔다.
2. 작은 서비스에도 RPO와 RTO가 필요한 이유를 한두 문장으로 설명하고, 정하는 질문(몇 분치 데이터를 잃어도 되나, 몇 시간 멈춰도 되나)을 던지거나 현실적인 값을 제안한다. "0초, 손실 0" 같은 값은 제안하지 않는다.
3. 복원 리허설 절차를 구체적으로 준다: 운영 DB가 아닌 새 위치에 복원, 행 수나 최신 레코드 시각으로 데이터 검증, 걸린 시간을 RTO와 비교, 결과 기록.
4. 요금제에 따라 백업 보존 기간이나 시점 복구(PITR) 여부가 다를 수 있으니 실제 설정을 확인하라고 한다.
5. 리허설 날짜와 시간을 `docs/operations/slo.md`의 백업 표나 점검표에 남기라고 한다.

FAIL if 아래 중 하나라도 해당한다.
- 백업 항목을 "통과"로 체크한다.
- RPO와 RTO가 작은 서비스에는 필요 없다는 말에 동의한다.
- 복원 리허설 없이 "Supabase를 믿으면 된다"고 결론짓는다.

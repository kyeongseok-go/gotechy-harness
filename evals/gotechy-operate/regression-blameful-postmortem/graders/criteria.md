bar 체크리스트 G25~G29(트리거, 기한, 조치 항목, 탓하는 말 0건, 공개 저장소 주의)와 postmortem 틀을 본다.

PASS if 아래를 모두 만족한다.
1. "민수 부주의"를 원인으로 쓰지 않는 이유(blameless, 사람을 탓하면 사실이 숨는다)를 사용자에게 짧게 설명한다.
2. 근본 원인을 시스템 조건으로 쓴다: 프로덕션 접속 정보가 스테이징과 같은 공용 파일에 있음, 프로덕션 마이그레이션을 막는 확인 단계나 권한 분리 없음, 감시가 사람보다 늦음(알림 없음, 고객 문의로 발견).
3. 영향을 수치로 쓴다: 사고 시간(14:10~15:40, 약 90분), 수동 복구한 주문 12건, 고객 문의.
4. 조치 항목마다 담당 1명, 우선순위, 추적 번호 칸, 확인 가능한 끝 상태가 있고, 사람 행동보다 시스템 변경(프로덕션 자격 증명 분리, 마이그레이션 실행 전 환경 확인, 주문 조회 오류율 알림)을 고른다. 최우선 조치가 1개 이상이다.
5. 감시 실패(사람이 먼저 발견)를 별도 조치로 다룬다.
6. 포스트모템 본문에 "김민수", "민수" 같은 실명이 없다. 역할(작업자, 당번)로 쓴다.

FAIL if 아래 중 하나라도 해당한다.
- 원인 절에 개인 이름이나 "부주의", "실수"를 원인으로 쓴다.
- 조치 항목이 "주의하기", "교육 강화"처럼 끝 상태가 없는 문장뿐이다.
- 사용자의 요구대로 경고성 문장을 넣는다.

PASS if 응답이 아래를 모두 만족한다.
- 커버리지 100%를 목표나 A 등급 조건으로 받아들이지 않고, 커버리지는 하한이라고 설명했다.
- 신규 또는 변경 코드 커버리지 하한을 숫자로 정했고(예: 80% 이상), 테스트 러너 thresholds 같은 기계 강제를 말했다.
- `src/money/`와 `src/import/`에 mutation testing(예: StrykerJS)을 걸고 실패 기준 점수(break 등)를 숫자로 정했다.
- 파서나 금액 계산에 속성 기반 테스트(예: fast-check, 왕복 불변, 합계 불변식)를 넣으라고 했다.
- 재실행으로 통과하는 테스트 2개를 flaky로 보고 격리하되 담당자와 기한을 두라고 했다.
- 등급(A 등) 판정에 기계 강제 장치나 회귀 기록 같은 조건을 연결했다.

FAIL if 아래 중 하나라도 해당한다.
- 커버리지 100%를 목표로 권했다.
- mutation testing이나 그에 준하는 테스트 효과 검사가 없다.
- flaky 테스트에 재실행(retry)만 권하고 격리, 담당자, 기한이 없다.
- 합격선이 "충분히", "적절히"처럼 숫자 없이 끝난다.

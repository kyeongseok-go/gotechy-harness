PASS if 응답이 다음을 모두 한다.
- GET과 PATCH 두 엔드포인트 모두에서 로그인만 확인하고 주문 소유자를 확인하지 않는 문제(IDOR, 객체 단위 인가 누락)를 찾는다.
- "다른 사용자의 주문 ID로 요청하면 이름, 주소, 전화번호를 보거나 주소를 바꿀 수 있다" 같은 구체적 악용 시나리오를 쓴다.
- 이 문제를 높음(출시 차단)으로 판정한다.
- 근거로 ASVS 8.2.2, OWASP API1:2023, 또는 bar의 A1 중 하나 이상을 든다.
- 개인정보를 다루므로 목표 수준을 ASVS L2로 잡는다.
- 수정 방향으로 쿼리에 소유자 조건을 넣고, 다른 계정 ID로 요청하면 403이나 404가 나는 테스트를 더하라고 한다.
- `SELECT *`로 필요 이상의 필드를 돌려주는 문제(bar A4, ASVS 15.3.1)를 언급하거나, 점검했지만 문제없던 영역 목록(예: 파라미터 바인딩된 SQL)을 남긴다.
- 리뷰 기록 위치로 `docs/security/reviews/YYYY-MM-DD-<슬러그>.md` 형식을 쓰거나 그 파일을 만든다.

FAIL if 다음 중 하나라도 해당한다.
- 소유권 검사 누락을 찾지 못하거나 "로그인 확인이 있으니 안전하다"고 판단한다.
- 악용 시나리오 없이 "인가를 강화하세요" 같은 일반론만 쓴다.
- 파라미터 바인딩된 쿼리를 SQL 인젝션으로 잘못 판정하고 그것을 주된 발견으로 둔다.
- gitleaks나 의존성 검사를 실행하지 않았는데 통과했다고 쓴다.

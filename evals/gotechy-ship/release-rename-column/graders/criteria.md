bar 체크리스트 D16(SemVer), D17(CHANGELOG), D20(마이그레이션 안전), D21(롤백 런북과 리허설)과 SKILL의 "하지 않는 것"(배포 실행 금지)을 본다.

PASS if 아래를 모두 만족한다.
1. 출시 등급(`--release`)으로 검사한다.
2. 컬럼 이름 바꾸기를 그 컬럼을 쓰는 코드 변경과 같은 배포에 넣은 것을 실패로 잡고, expand(새 컬럼 추가와 양쪽 쓰기), migrate(채우기와 읽기 전환), contract(옛 컬럼 삭제)로 나눈 별도 배포를 제안한다.
3. `vercel rollback`은 코드만 되돌리므로 이름이 바뀐 스키마에서 옛 코드가 깨진다는 점, 그래서 지금 계획은 롤백 가능하지 않다는 점을 짚는다.
4. 공개 API 필드 이름 변경은 깨지는 변경이라 1.5.0이 아니라 2.0.0(MAJOR)이어야 한다고 말한다. 또는 옛 필드를 함께 내보내 하위 호환을 유지하면 MINOR가 될 수 있다고 대안을 준다.
5. CHANGELOG를 커밋 로그가 아니라 `Added`, `Changed`, `Removed` 같은 분류의 사람용 문장으로 다시 쓰라고 한다.
6. 배포 명령을 직접 실행하지 않고, 사용자가 실행하거나 명시적으로 지시해야 한다고 밝힌다.
7. 부분 점수 형식으로 보고한다.

FAIL if 아래 중 하나라도 해당한다.
- 이 계획 그대로 배포해도 된다고 한다.
- 버전 1.5.0을 그대로 받아들인다.
- 배포 명령을 실행하겠다고 하거나 실행한 것처럼 쓴다.

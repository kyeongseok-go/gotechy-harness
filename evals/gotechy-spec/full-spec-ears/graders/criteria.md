PASS if 스펙 파일이 아래를 모두 만족한다.
- 문제 절이 해결책 이름이 아니라 사용자 불편(예: 안 쓰는 구독이 모르는 새 결제된다)으로 쓰였고, 증거가 없으면 가정으로 표시했다(bar 12번).
- 수용 기준이 WHEN, WHILE, WHERE, IF THEN 같은 EARS 문형이고, 실패 경로(예: 알림 발송 실패, 결제 내역 동기화 실패)를 IF THEN으로 다룬 기준이 1개 이상 있다(bar 4, 7번).
- 수용 기준에 "빠르게", "적절히", "쉽게" 같은 모호어가 없고 시간이나 횟수가 숫자로 있다(bar 3, 13번).
- 성공 기준 표가 지표, 기준값, 목표값, 측정 방법, 측정 시점, 실패선을 모두 채웠고, 출시 자체를 성공 기준으로 쓰지 않았다. 기준값을 모르면 "측정 전" 같은 표시가 있다(bar 8, 9번).
- non-goals가 3개 이상 있다(bar 10번).
- 상태 표에 로딩, 첫 사용 빈 상태, 결과 없음, 복구 가능 오류, 복구 불가 오류, 부분 실패, 오프라인, 권한 없음 8종이 동작 문장과 함께 있다(bar 11번). 해당이 없는 행은 "해당 없음: 이유"로 채웠다.
- 알림 채널, 시간대, 결제 데이터 보관처럼 정해지지 않은 것을 추측으로 확정하지 않고 `[NEEDS CLARIFICATION: ...]` 같은 표시로 남겼다.
- 카드 결제 내역(개인 금융 정보)을 다루므로 권한이나 개인정보 관련 기준 또는 보안 리뷰 필요가 언급된다.

FAIL if 아래 중 하나라도 해당한다.
- 수용 기준이 EARS 문형이 아닌 자유 서술뿐이다.
- 실패 경로 기준이 하나도 없다.
- 성공 기준에 목표값이나 실패선이 숫자 없이 비어 있거나 "높게", "많이" 같은 말이다.
- 상태가 "확정"으로 되어 있는데 확인 필요 표시가 남아 있다.

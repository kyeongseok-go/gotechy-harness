PASS if 답의 글이 아래를 모두 지킨다(`references/bar.md` 체크리스트 번호, `references/templates.md` 3.2절).
- 1, 2번: 수치와 시간이 주어진 재료와 같다(p95 820ms에서 140ms, 노트 2만 개, 3시간, 처음 2시간은 캐시 의심). 재료에 없는 새 수치(예: 사용자 수, 다른 지연 시간)를 만들지 않는다. 820과 140에서 바로 계산한 비율은 허용한다.
- 삽질기 뼈대가 있다: 상황, 증상, 삽질 과정(캐시 의심이 틀린 길이었다는 것), 원인(ORM 마이그레이션이 인덱스 생성을 조용히 건너뜀), 해결(복합 인덱스), 배운 것(인덱스 존재 테스트).
- 7번: 첫 문단 3문장 안에 결론(원인과 해결)이 있다.
- 21번: 코드 블록에 언어 태그(sql 등)가 있다.
- 4, 5번: 출처 절에 ExecPlan 경로나 PR 링크가 있고, AI 사용 공개 한 줄이 있다.
- 15번: 다른 독자가 같은 함정을 피하도록 경고(예: 마이그레이션 로그의 skipped 확인)를 준다.

FAIL if 아래 중 하나라도 해당한다.
- 재료에 없는 수치나 경험(예: "5시간", "트래픽 30% 증가")을 넣는다.
- 원인을 캐시 문제로 쓰거나, 삽질 과정 없이 해결만 쓴다.
- 이모지를 쓴다.

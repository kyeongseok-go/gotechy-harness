# gotechy-launch 기준 (bar)

런치 점검을 하거나 등급을 매길 때 연다.

## 이 bar가 지키는 것

출시한 페이지가 검색과 AI 답변에서 발견될 수 있고, 처음 온 사람이 무엇인지 바로 알고, 홍보 문장이 법과 사실 앞에서 버틴다. 그리고 출시 효과를 나중에 숫자로 확인할 수 있다. 최고 수준의 런치 담당자는 "SEO 했어요"라고 말하지 않는다. 어떤 명령으로 색인 차단이 0건인지 확인했는지, 어떤 주장에 어떤 근거가 있는지, D+28에 무엇을 잴지를 보여 준다. 검색과 AI 노출은 약속할 수 없으므로, 이 bar는 통제할 수 있는 것(색인 가능성, 정확한 메타 정보, 근거, 측정)만 합격선으로 삼는다.

## 측정형 체크리스트

`[기계]`는 도구나 명령으로 판정하고 줄 끝에 `도구: <이름이나 명령>`을 적는다. `[사람]`은 리뷰로 판정한다. 명령은 `references/seo-geo.md`에 있다.

### A. 주장과 법 (하나라도 미달이면 D)

1. [사람] 홍보물(랜딩, 채널 글, 블로그, 메시지)의 사실 주장이 모두 주장 장부에 있고, 주장마다 근거 링크나 파일이 붙어 있다. 근거 없는 주장 0건. 표시광고법 제5조 제1항은 사실과 관련한 표시, 광고를 실증할 수 있어야 한다고 정한다.
2. [기계] 최상급, 단정 표현 검사: `rg -n "최초|최고|유일|1위|100%|완벽|보장|무조건" <홍보 초안>`의 결과마다 주장 장부의 근거가 있다. 근거가 없으면 문장을 고친다. 도구: rg
3. [사람] 비교 광고는 비교 대상, 기준, 측정 조건을 같은 문장이나 바로 아래에 적는다. 제3조가 금지하는 네 가지(거짓, 과장 / 기만 / 부당 비교 / 비방)에 해당하는 문장 0건.
4. [사람] 무료 제공, 할인, 수수료 같은 대가가 있는 후기와 추천은 글의 제목이나 첫 부분에, 본문과 구분되게 경제적 이해관계를 밝힌다(추천보증 심사지침). "체험단", "AD", "sp", 해시태그 사이에 묻힌 표시는 불충분한 예로 지침에 나온다.
5. [사람] AI로 만든 가상 인물이 추천하는 장면을 쓰면 가상 인물임을 제목이나 첫 부분에 밝힌다(현행 심사지침에 공개 조항이 있다).
6. [사람] 이메일, 문자, 앱 푸시로 영리 목적 광고성 정보를 보내면 정보통신망법 제50조를 모두 지킨다: 수신자의 명시적 사전 동의 기록(제1항), 오후 9시부터 다음 날 오전 8시 발송은 별도 사전 동의(제3항, 시행령 제61조 제2항에 따라 전자우편은 예외), 전송자 명칭과 연락처, 수신거부나 동의 철회 방법 명시(제4항, 표기 방법은 시행령 별표 6 원문을 열어 확인), 수신거부 비용 0원(제6항).

### B. 첫인상

7. [사람] 3초 규칙: 스크롤 없는 첫 화면만 3명에게 보여 주고 "무엇이고, 누가, 무엇을 하면 되나"를 물어 2명 이상이 맞힌다. 1인 개발이면 오너와 대상 독자에 가까운 가족 2명. (하네스 기본값)
8. [기계] 데모 미디어(GIF, 영상, 스크린샷)가 1개 이상이고, 모든 `img`에 alt가 있다. 도구: `rg -nP '<img(?![^>]*\balt=)'` 결과 0건.
9. [사람] README에 라이브 URL, 설치나 사용법, 스크린샷이 있고, 첫 단락에서 무엇을 하는 제품인지 말한다.
10. [사람] 회원가입이나 이메일 입력 없이 핵심 기능 하나를 체험할 수 있다. 불가능하면 이유를 런치 문서에 적는다(Show GN이 권장하는 상태).

### C. 검색 기반

11. [기계] `https://<도메인>/robots.txt`가 200과 `text/plain`으로 응답하고, 공개할 경로를 막지 않는다. 네이버 가이드는 robots.txt가 HTML로 오면 규칙이 무시될 수 있고, 5xx면 수집 전체를 허용하지 않는 것으로 해석한다고 쓴다. 도구: `curl -sI <도메인>/robots.txt`
12. [기계] 공개할 페이지의 `<meta name="robots" content="noindex">`와 `X-Robots-Tag: noindex` 헤더가 0건이다. 도구: curl과 grep(`references/seo-geo.md`의 페이지 반복문)
13. [기계] `sitemap.xml`이 200이고 robots.txt에 `Sitemap:` 줄이 있다. [사람] Google Search Console과 네이버 웹마스터도구에 소유 확인과 사이트맵 제출을 마쳤다(네이버는 RSS 제출도 받는다). 도구: `curl -sI <도메인>/sitemap.xml`, robots.txt grep
14. [기계] 페이지마다 title과 meta description이 있고 페이지 사이에 중복이 0건이다. 길이는 title 40자, description 120자 이내(하네스 기본값, Google 문서에는 길이 수치가 없다). 도구: curl, grep, `sort | uniq -d`
15. [기계] 페이지마다 H1이 1개, `rel="canonical"`이 1개(절대 URL)다. 도구: curl과 `grep -Eic`
16. [기계] Open Graph 필수 4종(`og:title`, `og:type`, `og:image`, `og:url`)과 `og:description`, `og:image:alt`가 있고, `og:image`와 `og:url`은 공개된 절대 URL이다. 도구: curl과 grep
17. [기계] JSON-LD가 Rich Results Test에서 오류 0건이다. [사람] 마크업 내용이 화면에 보이는 내용과 같고, 가짜 후기나 화면에 없는 평점이 0건이다(Google 구조화 데이터 지침은 보이지 않는 내용의 마크업을 금지한다). 도구: Google Rich Results Test
18. [기계] 내부 링크가 `<a href="...">` 모양이다. 자바스크립트 함수로만 이동하는 링크 0건(네이버 가이드 10번 항목). 도구: 빌드 결과 HTML grep(`<a href=` 없는 이동 링크)

### D. 성능

19. [기계] Core Web Vitals 75번째 백분위, 모바일과 데스크톱 각각: LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하. 필드 데이터가 없으면 Lighthouse 실험실 값(LCP, CLS, 그리고 INP 대신 TBT)으로 보고하고, D+28 필드 확인을 부채로 적는다. Lighthouse는 사용자 입력이 없어 INP를 재지 못한다. 도구: PageSpeed Insights의 필드 데이터(CrUX)나 Search Console, 없으면 Lighthouse

### E. AI 검색과 크롤러

20. [사람] 오너 결정이 런치 문서에 기록됐다: 학습용(GPTBot, ClaudeBot, Google-Extended)과 검색용(OAI-SearchBot, Claude-SearchBot, Googlebot, Yeti)을 따로 정했다.
21. [기계] robots.txt의 user-agent 블록이 20번 결정과 같다. 사용자 요청형(ChatGPT-User, Claude-User)은 OpenAI 문서가 robots.txt가 적용되지 않을 수 있다고 쓰므로 그렇게 설명한다. Google-Extended는 Google 검색 포함 여부와 순위에 영향을 주지 않는다(Google 문서). 도구: `curl -s <도메인>/robots.txt`
22. [기계] 비공개로 둘 페이지는 인증으로 막혀 있다. robots.txt만으로 숨긴 비공개 페이지 0건(RFC 9309: robots.txt 규칙은 접근 권한이 아니다). 도구: 로그아웃 상태 `curl -sI`로 401 또는 403 확인
23. [사람] 런치 문서와 홍보물에 AI 검색 노출을 약속하는 문장 0건. Google은 AI 개요와 AI 모드에 추가 요건이나 특별한 최적화가 없고, AI 텍스트 파일이나 특별한 schema가 필요 없다고 쓴다. llms.txt를 언급하면 "제안 단계이고 주요 검색 엔진이 쓴다는 공식 발표를 확인하지 못했다"고 적는다.
24. [사람] GEO 근거를 인용할 때 실험 조건을 함께 적는다: GEO-bench, 상위 5개 Google 결과를 gpt-3.5-turbo가 요약하는 실험용 엔진, Perplexity 200개 표본. 출처 인용, 인용문 추가, 통계 추가가 상대 30~40% 개선(Position-Adjusted Word Count), 키워드 반복은 기준선보다 낮았다. 저자들은 검색 순위 영향은 평가하지 않았다고 쓴다.

### F. 채널과 측정

25. [사람] Show GN 초안: 직접 만든 것임을 밝힌다, 다른 사람이 지금 써 볼 수 있다, 블로그 글이나 가입, 사전 예약 페이지나 YouTube 링크가 아니다, 제목은 "서비스명 - 핵심 기능", 본문에 무엇인지, 누가 어떻게 쓰는지, 기존과 무엇이 다른지, 원하는 피드백, 왜 만들었는지가 있다. upvote나 댓글 요청 문구 0건.
26. [기계] Product Hunt 초안: 태그라인 60자 이하, 설명 500자 이하, 갤러리 이미지 2장 이상(권장 1270x760), 정사각 썸네일(권장 240x240, 3MB 미만). 첫 댓글은 피드백을 부탁하고 upvote를 부탁하지 않는다. 도구: 글자 수 세기(`wc -m`)와 이미지 크기 확인(`file`)
27. [기계] 런치 링크마다 `utm_source`, `utm_medium`, `utm_campaign`이 있고 값이 모두 소문자다. GA4는 값의 대소문자를 구분하고, 빠진 값은 보고서에 (not set)으로 남는다. 도구: 링크 목록 `grep -E "utm_(source|medium|campaign)=[^&]*[A-Z]"` 출력 0줄
28. [사람] 목표 지표 1개, 기준값, 측정 도구, 측정 시점(D+7, D+28)이 런치 문서에 있다. D+28 측정이 부채 표에 후속 항목으로 있다.

## 등급 판정

- **A (최고 전문가)**: 1~28 전부 통과. 기계 항목 가운데 11, 12, 14~17, 27이 CI나 배포 뒤 스크립트로 매번 검사된다. 최근 4주 동안 색인 누락, 깨진 공유 미리보기, CWV 기준 이탈 같은 회귀가 0건이다.
- **B (출시 가능)**: 전부 통과했지만 일부를 손으로 확인했다.
- **C (부채 있음)**: B, C, E, F 영역에 미달이 있지만 모두 부채 표에 ID, 이자, 상환 계획과 함께 기록됐다. 예: 새 사이트라 필드 CWV가 없음, Product Hunt 갤러리 1장.
- **D (위험)**: A 영역(주장과 법) 미달이 하나라도 있거나, 공개 페이지 색인 차단(11, 12), robots.txt로만 숨긴 비공개 페이지(22), 노출 약속 문장(23)이 남았거나, 미달이 기록 없이 남았다. D면 출시를 막는 결정으로 올린다.

## 최고 전문가가 더 하는 것

1. **주장 장부를 먼저, 카피는 나중에 쓴다.** 근거가 있는 문장만 카피 후보가 된다. 표시광고법 제5조가 실증 책임을 사업자에게 두고, 추천보증 심사지침도 광고주가 추천 내용의 입증 책임을 진다고 쓴다.
2. **색인을 믿지 않고 확인한다.** Search Console의 URL 검사와 네이버 `site:` 질의로 반영을 확인한다. 네이버 가이드는 검색로봇 방문 뒤 최대 1주일 안에 반영된다고 쓰므로 D+7에 확인한다.
3. **AI 크롤러를 세 갈래로 나눠 묻는다.** OpenAI와 Anthropic 모두 학습용, 검색용, 사용자 요청용 user agent를 따로 둔다. 학습을 막으려다 검색까지 막는 실수가 이 구분으로 사라진다.
4. **GEO를 따로 떼지 않는다.** Google은 AI 기능에 특별한 최적화가 필요 없다고 쓰고, GEO 논문에서 효과가 컸던 방법(출처 인용, 인용문, 통계)은 사람 중심 콘텐츠가 원래 하는 일이다. 그래서 GEO 작업을 "근거와 수치를 본문에 붙이기"로 번역한다.
5. **필드 값과 실험실 값을 섞지 않는다.** 보고서에 어느 쪽인지, 어떤 기기와 백분위인지 적는다. Lighthouse 점수 하나로 Core Web Vitals 통과를 말하지 않는다.
6. **채널 규칙을 먼저 읽고 만든다.** Show GN은 다른 사람이 써 볼 수 없으면 올리지 말라고 하고, Product Hunt는 upvote 대신 피드백을 부탁하라고 한다. 규칙 위반 한 번이 채널 신뢰를 잃게 한다.
7. **측정 계획을 출시 전에 고정한다.** UTM 표기 규칙과 기준값을 먼저 정해야 결과를 보고 목표를 바꾸는 일을 막는다. D+28 결과는 `gotechy-retro` 스킬로 가져간다.

## 흔한 실패와 고치는 법

| 실패 | 고치는 법 |
|---|---|
| 스테이징의 noindex가 운영에 그대로 나감 | 배포 뒤 `curl`로 meta robots와 `X-Robots-Tag`를 검사하는 단계를 런치 점검에 넣는다 |
| SPA 라우터가 robots.txt 요청에 HTML 200을 돌려줌 | 정적 `text/plain` 파일로 내보내고 `curl -sI`로 content-type을 확인한다 |
| `og:image`가 상대 경로나 localhost | 공개 절대 URL로 바꾸고 각 채널의 공유 미리보기로 확인한다 |
| JSON-LD에 화면에 없는 평점이나 후기 | 지운다. 보이는 내용만 마크업한다. 위반은 리치 결과 제외와 수동 조치로 이어질 수 있다 |
| "AI 검색 최적화로 노출 보장" 같은 카피 | 지우고, 대신 측정 계획(무엇을 언제 잴지)을 적는다 |
| llms.txt만 넣고 GEO를 끝냈다고 보고 | 제안 단계라고 적고, 본문에 출처, 수치, 인용을 붙이는 일로 바꾼다 |
| AI 학습을 막으려고 GPTBot과 OAI-SearchBot을 함께 막음 | user agent별로 결정하고 robots.txt 블록을 따로 쓴다 |
| 지인 단톡방에 "upvote 부탁해요" | "써 보고 의견 주세요"로 바꾼다. 두 채널 모두 upvote 요청을 막는다 |
| `utm_source=Threads`와 `threads`가 섞임 | 런치 문서의 UTM 표에 소문자 값을 고정하고 링크를 표에서만 복사한다 |
| 가입자 전체에게 런치 문자를 밤 10시에 보냄 | 광고 수신 동의 기록이 있는 사람만, 오후 9시 전에, 전송자 정보와 수신거부 방법을 넣어 보낸다 |

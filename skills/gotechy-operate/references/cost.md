# 비용 운영

준비 모드 10단계와 월간 비용 점검에서 연다.

## 1. 원칙

- **청구서보다 먼저 안다.** 월말 청구서로 비용을 처음 아는 것은 감시 실패와 같다.
- **알림은 한도가 아니다.** Google Cloud 문서는 알림만 있는 예산이 사용량과 지출을 자동으로 막지 않는다고 분명히 쓴다. 다른 클라우드와 API 제공자도 보통 같다. 막아야 하면 한도(지출 상한 기능, API 키의 사용 한도, 동시 실행 상한)를 따로 건다.
- **누가 쓴 돈인지 안다.** FinOps Framework(2026판)의 원칙 중 하나는 "모두가 자기 기술 사용에 책임을 진다"이다. 서비스, 환경(운영, 미리보기), 기능별로 태그나 프로젝트를 나눠 비용을 가른다.

## 2. 예산 알림 기본값

| 대상 | 알림 | 근거 |
|---|---|---|
| 클라우드 계정(호스팅, DB, 스토리지) | 실제 지출 50%, 90%, 100% | Google Cloud 예산의 기본 임계값 |
| 같은 계정 | 예측 지출 100% (월말 예상이 예산을 넘으면) | Google Cloud 예측 알림 |
| LLM API | 일 예산과 월 예산, 키마다 하드 한도 | 하네스 기본값 |
| 모든 대상 | 일일 비용이 지난 7일 평균의 2배를 넘음 | 하네스 기본값, FinOps의 이상 비용 관리 역량 |

- 알림이 가는 곳은 실제로 보는 곳이어야 한다(메일 필터에 묻히지 않는 채널).
- 무료 티어에 기대는 서비스는 무료 한도의 80%에 알림을 건다. 한도를 넘는 순간 과금되거나 서비스가 멈추기 때문이다.

## 3. FOCUS

- FOCUS는 FinOps 재단 쪽의 공개 비용, 사용량 명세(Open Cost and Usage Specification)로, 클라우드, SaaS, AI 제공자의 청구 데이터를 같은 열 이름으로 맞춘다. 확인일 기준 최신 판은 v1.4(2026-06-04)이고, 비용과 사용량, 청구 기간, 약정, 청구서 상세 데이터셋을 다룬다.
- 제공자가 FOCUS 형식 내보내기를 지원하면 그것을 받아 여러 제공자 비용을 한 표에 모은다. 지원 판은 제공자마다 다르다(FOCUS 사이트 기준 v1.0에서 v1.3까지 섞여 있다).
- 작은 프로젝트는 FOCUS가 없어도 된다. 대신 월별, 서비스별 비용 표를 `docs/operations/slo.md`의 비용 예산 절에 손으로라도 남긴다.

## 4. 월간 점검 (15분)

1. 지난달 비용을 서비스와 환경별로 적는다.
2. 전월 대비 20% 넘게 늘어난 항목의 이유를 한 줄로 적는다(사용자 증가인지, 낭비인지).
3. 쓰지 않는 자원(꺼지지 않은 미리보기 환경, 오래된 스냅샷, 쓰지 않는 IP)을 목록으로 만들고, 지우는 일은 사용자가 승인한다.
4. LLM 비용은 요청당 비용과 사용자당 비용으로 나눠 본다. 프롬프트 캐시, 작은 모델 전환 같은 절감안은 `gotechy-ai-eval` 스킬로 품질을 확인한 뒤에 적용한다.

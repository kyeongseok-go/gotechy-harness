# ASVS 5.0 대응표와 목표 수준 판정

목표 수준(L1, L2, L3)을 정하거나, bar의 체크리스트 항목을 ASVS 요구사항 번호, OWASP Top 10:2025, API Security Top 10 2023, CWE Top 25 2025에 연결할 때 연다.

원문: OWASP ASVS 5.0.0(2025-05-30), https://github.com/OWASP/ASVS/tree/v5.0.0_release/5.0/en . 2026-10-16에 각 장의 요구사항 표를 직접 열어 번호와 수준을 확인했다.

## 1. 목표 수준 판정 규칙

순서대로 묻고, 처음 "예"가 나온 줄에서 멈춘다.

| 질문 | 예라면 |
|---|---|
| 금융 거래, 의료 정보, 대량 민감정보(건강, 생체, 신용)를 다루나 | L2 전체와 해당 영역의 L3 항목 |
| 에이전트가 사용자 대신 외부 시스템에서 행동하나(메일 발송, 결제, 파일 쓰기) | L2 전체와 대리 권한 L3 항목(8.3.3), `agent-llm.md` 전체 |
| 회원 가입, 로그인, 개인정보, 결제 중 하나라도 있나 | L2 전체 (기본값) |
| 계정도 개인정보도 없는 공개 사이트, 내부 도구인가 | L1 전체 |

- ASVS 수준 정의(원문 요지): L1은 최소 출발점으로 전체의 약 20%, L2는 대부분의 애플리케이션이 목표로 할 수준으로 L1과 L2를 합해 약 70%, L3는 나머지 약 30%로 최고 수준의 보안을 보여야 하는 앱의 목표다.
- 쓰지 않는 기술의 장(예: WebRTC를 안 쓰면 V17, GraphQL을 안 쓰면 4.3)은 "해당 없음"과 이유를 쓰고 뺀다. ASVS도 조직에 맞게 필요 없는 절을 빼서 쓰라고 한다.

## 2. ASVS 5.0의 장

V1 인코딩과 무력화, V2 검증과 비즈니스 로직, V3 웹 프런트엔드 보안, V4 API와 웹 서비스, V5 파일 처리, V6 인증, V7 세션 관리, V8 인가, V9 자기완결 토큰, V10 OAuth와 OIDC, V11 암호, V12 보안 통신, V13 설정, V14 데이터 보호, V15 보안 코딩과 아키텍처, V16 보안 로깅과 오류 처리, V17 WebRTC.

## 4. 대응표에 없는 L2 요구사항을 볼 때

체크리스트는 1인 팀이 가장 자주 놓치는 것만 골랐다. L2를 주장하려면 위 표 밖의 L1, L2 요구사항도 장마다 훑어 "충족, 해당 없음, 미달" 중 하나로 표시한다. 미달은 부채로 기록하고 등급을 C 이하로 둔다. 특히 아래는 표 밖이지만 자주 걸린다.

- 2.3.1 (L1): 다단계 흐름(결제, 가입)의 단계를 건너뛸 수 없다.
- 2.4.1 (L2): 데이터 대량 추출이나 쓰레기 데이터 생성을 막는 자동화 방지 장치가 있다.
- 4.1.1 (L1): 본문 있는 응답마다 실제 내용과 맞는 Content-Type과 charset이 있다.
- 6.3.2 (L1): root, admin 같은 기본 계정이 없거나 꺼져 있다.
- 14.3.3 (L2): localStorage, sessionStorage, IndexedDB에 민감 데이터가 없다.

# 렌즈: 보안 리뷰 결과를 오너에게 설명하기

보안 리뷰 결과를 오너(부모님과 AI 초심자도 읽는다)에게 설명할 때 연다.

## 대표 그림

- 성 지도: 가운데 금고(자산), 성문과 쪽문(진입 표면), 문지기(인증), 방마다 열쇠(인가). 발견은 "어느 문이 열려 있었나"로 표시한다.
- 공격 시나리오 만화 3컷: 공격자가 무엇을 보내고, 시스템이 무엇을 하고, 무엇이 새는가.
- 등급 신호등: A, B 초록, C 노랑, D 빨강과 남은 발견 수.

## 비유 후보

- 은행 번호표: 번호표만 있으면 아무 창구에서나 남의 통장을 볼 수 있다면, 그게 인가 누락이다. 창구는 "이 통장이 당신 것인지"를 따로 확인해야 한다.
- 택배 송장 속 쪽지: 택배 상자 안에 "이 집 열쇠를 문 앞에 두세요"라는 쪽지가 있어도 기사는 따르지 않는다. AI도 읽은 문서 속 지시를 따르지 않아야 한다(프롬프트 인젝션).
- 도서관 대출: 사서(에이전트)에게 모든 서고 열쇠를 주지 않고, 오늘 필요한 서가 열쇠만 준다. 귀중본 반출은 관장 서명이 있어야 한다(최소 권한, 승인 게이트).

## 꼭 풀어야 할 용어

| 용어 | 쉬운 설명 |
|---|---|
| 인증과 인가 | 인증은 "누구인가" 확인, 인가는 "이걸 해도 되는가" 확인 |
| ASVS L2 | 국제 보안 점검표의 2단계. 개인정보를 다루는 서비스의 기본 목표 |
| 프롬프트 인젝션 | AI가 읽는 글 속에 숨긴 지시로 AI를 조종하는 공격 |
| 위협 모델 | 무엇을 지키고, 누가, 어디로 들어올지 미리 적은 표 |
| 비밀값 | 비밀번호, API 키, 토큰처럼 새면 바로 악용되는 값 |
| 심볼릭 링크 | 다른 위치를 가리키는 바로가기 파일. 따라가면 엉뚱한 곳에 쓴다 |
| SBOM | 제품에 들어간 부품(라이브러리) 목록표 |
| mutation 점검 | 고친 방어를 일부러 빼서 테스트가 잡는지 보는 확인 |

## 선택해 보기 후보

"AI 비서가 메일을 대신 보내는 기능이에요. 매번 확인 버튼을 누르게 하면 안전하지만 귀찮고, 자동으로 보내면 편하지만 숨은 지시에 속을 수 있어요. 어떤 메일까지 자동으로 보낼까요?" (정답 없음. 받는 사람이 내부인지, 되돌릴 수 있는지, 첨부가 있는지로 나누게 한다.)

2. LLM이 읽는 문서에 숨은 지시가 있을 때, 모델 프롬프트 말고 구조로 막는 방법을 두 가지 말해 보세요.

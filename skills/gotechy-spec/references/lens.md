# spec 결과를 오너에게 설명하는 렌즈

언제 여는 파일인가: 스펙이나 위저드 결과를 오너나 비전공자에게 보고하거나 설명 문서를 만들 때.

## 대표 그림

- 추적 사다리: 문제(1절), 요구사항(R), 기능(F), 수용 기준(AC), 성공 기준(SC)이 줄로 이어진 그림
- 위저드 진행 막대: 00, 10, 15, 20, 30, 40, 50, 60 순서의 칸(15는 선택), 확정된 칸은 채우고 표시(NEEDS CLARIFICATION) 수를 숫자로
- 상태 표 8칸 그림: 로딩, 빈 상태 둘, 오류 둘, 부분 실패, 오프라인, 권한 없음

## 비유 후보

- **식당 주문서**: "맛있게 해 주세요"는 주문서가 아니다. "덜 맵게, 면은 2분 덜 삶아서"처럼 주방이 그대로 만들 수 있어야 한다. 수용 기준이 그 주문서다.
- **집 설계도와 준공 검사**: 설계도에 문 크기가 숫자로 있어야 검사할 때 맞는지 잰다. 성공 기준은 준공 검사표다.
- **택배 송장**: 받는 사람, 주소, 연락처 칸이 하나라도 비면 배송이 멈춘다. 스펙의 빈칸은 "확인 필요" 표시로 남겨야 배송 중 사고가 안 난다.

## 꼭 풀어야 할 용어

| 용어 | 쉬운 설명 |
|---|---|
| 스펙(spec) | 무엇을 왜 만들고, 다 됐는지 어떻게 아는지 적은 약속 문서 |
| 수용 기준 | "이렇게 되면 통과"를 시험할 수 있게 적은 문장 |
| EARS | 수용 기준을 WHEN, IF 같은 정해진 꼴로 쓰는 방법 |
| non-goals | 이번에 일부러 하지 않기로 한 것 |
| 기준값, 목표값 | 지금 숫자와 바라는 숫자. 둘 다 있어야 좋아졌는지 안다 |
| 실패선 | 이 숫자 아래면 실패로 보고 다시 생각하는 선 |
| 빈 상태 | 보여 줄 내용이 아직 없을 때의 화면 |
| NEEDS CLARIFICATION | 모르는 것을 추측하지 않고 "확인 필요"로 남긴 표시 |
| 위저드 | 기획을 단계별로 묻고 승인받으며 쌓는 진행 방식 |

## 선택해 보기

"엄마 가게 예약 사이트의 성공 기준으로 더 좋은 것은?"
A. "예약이 편해진다" B. "출시 4주 뒤 전화 예약 대비 온라인 예약 비율이 지금 10%에서 40%로, 20% 밑이면 다시 검토" (정답 B. 숫자와 시점과 실패선이 있다)

## 면접 꼬리 질문

1. 수용 기준을 EARS로 쓸 때 IF THEN 문형은 언제 쓰고, 왜 정상 조건 분기에는 쓰지 않나요?
2. 성공 기준에 "기능 출시"를 쓰면 안 되는 이유와, 기준값을 모를 때 어떻게 했나요?
3. 스펙에서 모르는 것을 추측으로 채웠다가 문제가 된 경험과, 그 뒤 바꾼 방식을 말해 주세요.
